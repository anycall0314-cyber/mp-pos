## 規則

### 登入 / RBAC

DRF Token auth(`Authorization: Token xxx`),`/auth/login` `/auth/me` `/auth/logout`。`UserProfile`(tenants app)綁定 User 1:1,記錄 `role` / `tenant` / `default_warehouse` / `is_warehouse_locked`。三種角色:**platform_admin**(跨所有 tenant,只用 `/platform/*` 後台)、**tenant_admin**(自家 tenant 全權限、不鎖倉、看所有報表)、**tenant_user**(鎖在 default_warehouse、只看 / 只能操作自己倉)。`TenantMiddleware` 從 `request.user.profile.tenant` 解析 tenant

### 員工帳號權限(逐項勾選)

2026-10-10 起(owner:「我要針對員工帳號設定各種權限」;他選每個帳號逐項勾選、預設全開、帳號照舊在平台管理建)。**清單與判斷只有 `backend/apps/tenants/abilities.py` 一份**:每一項有代碼、名稱(同一類字數一樣)、分類。記的是**關掉的項目**(`UserProfile.denied_abilities`,空的 = 全開)—— ### 身份別與帳號例外

2026-10-27 起(owner:「我要做身份別，比如管理者，店長，門市，行政（可自行添加刪除），或是針對特定帳號做權限調整」「未來權限會擴充非常多，目前採所有權限用橫式會裝不下」;他選「一直跟著身份別」「管理者內建、固定全開」「清單 + 整頁打開」)。
- **身份別**(`tenants.StaffRole`:公司、名稱、`denied_abilities`):一組勾選,寫法跟帳號的一樣(代碼 = 關、`+代碼` = 預設不開的項目打開;跟預設一樣的不記)。名稱同一家不能重複、最多 20 字、不能叫「管理者」。新公司建立時給 店長 / 門市 / 行政(勾選照預設;`services.seed_staff_roles`,只給新公司,刪掉的不會自己長回來)。
- **帳號跟著身份別走**(`UserProfile.staff_role`):帳號關掉的 = (身份別關掉的 − 帳號的 `+代碼`)∪ 帳號的代碼(兩個都記到同一項算關);帳號的 `denied_abilities` 只記**例外**(跟身份別不一樣的;設回跟身份別一樣就拿掉)。改身份別的勾選,那個身份的人一起變。沒有身份別 = 照預設(跟 2026-10-27 以前的算法一模一樣)。**換身份別 = 例外清掉、完全照新身份別**;同一次送的 `abilities` 再跟新身份別比,記成新的例外。
- **「管理者」= 公司管理員帳號**(`tenant_admin`):不在表裡、固定全開、這一頁不能改;只有它能管帳號、看成本、核准盤點等。管理員帳號照舊在平台管理開。要讓店長也能做那些事,就把那件事加成可以勾的項目(`abilities.py`)。
- **刪身份別**:還有帳號是那個身份別就擋(400「還有 N 個帳號是…」;外鍵 `PROTECT`,改成空的等於放寬)。刪與把帳號換成那個身份別都先鎖身份別那一列(同時發生不會 500,有兩條連線的測試)。
- **管理員在這裡開店員帳號**(`POST /staff-accounts/`):名字、帳號(建議 = 公司代碼 + 下一個流水號,例 JB005;全系統不能重複、大小寫不同也算重複)、密碼、門市(空 = 全部)、鎖在這間門市(要先選門市)、身份別(公司有身份別就一定要選;預設帶**最多人用的**,不是排第一的店長)、例外。同時建一位同名的業務員(代號 = 帳號;代號被用過就擋)。改名字(連業務員一起改)、門市、鎖門市、身份別、例外:`PATCH /staff-accounts/<id>/`(只送要改的)。身份別:`POST /staff-roles/`、`PATCH / DELETE /staff-roles/<id>/`。全部只有管理員、只有自己公司。平台後台開的店員也帶最多人用的身份別;平台把帳號換到別家公司時,身份別換成新公司最多人用的、舊公司給的例外清掉(複審抓到的:不然舊公司多開的項目在新公司還有效)。
- **「自訂分析要先開另外幾張」**照舊:這一次要開的項目開了也用不了 → 400「「自訂分析」要先開:…」。畫面只送改過的項目,沒動到的連帶關掉不會被擋;畫面上開著但用不了的那一項標「要先開…」。
- **公司備份**:`StaffRole` 登記成 ACCOUNT(不整列匯出);`accounts.json` 每個店員帶 `staff_role: {name, denied_abilities}`(沒有 = `null`;更早的備份沒有這一格 = 沒有身份別)。搬到新環境照名稱建回來(同名只建一個),帳號的例外跟它比,權限跟原本一樣;就地還原跟帳號一樣不動。
- **畫面**(`pages/settings/StaffAccountsPage.tsx`):分頁「帳號 / 身份別」;清單點一列整頁打開(`StaffAccountForm` / `StaffRoleForm`,不開彈窗;改過沒存回清單要按兩次)。權限直的排(`AbilityChecklist`):一類一區、每類一個整類勾選(半選 / 全選)、跟身份別不一樣的標「例外」+「回到身份別」。帳號頁的重設密碼、停用 / 啟用按下去就生效,跟儲存無關。規則在 `lib/staffAccess.ts`。

### 帳號密碼與收回

2026-10-19 起(owner:「登入後沒有修改密碼的選項」「還有離職員工也要有移除的權限」)。**自己改密碼**:側欄帳號旁「密碼」→ `/account/password`(`POST /api/v1/account/password/`,要打對目前的密碼;**打錯回 400 不是 401**,401 會讓畫面登出;**不放在 `/auth/` 底下**,`/auth/` 不受公司維護鎖管)。**老闆管店員帳號**:員工帳號頁店員那一列「重設密碼 / 停用帳號(按兩次)/ 啟用帳號」(`POST /api/v1/staff-accounts/<id>/access/`,`{password}` 或 `{is_active}`;只有公司管理員、只能動自己公司的 `tenant_user`,管理員帳號照舊找平台;停用連業務員一起停、啟用一起開;**不刪帳號**,單據指著他)。規則只有 `auth_views.password_problem` 一份(至少 4 碼、前後不能有空白 —— 登入那一格會去掉前後空白);**換密碼一律走 `set_password_and_sign_out`**:作廢那個帳號的 token(一帳號一把),別台都要重新登入;自己改的回一把新 token,前端用 `swapToken` 換上(同一個人,不算換登入狀態);平台重設也走它。測試 `tenants/test_passwords.py`

### 同一帳號只能一個位置登入

2026-10-24 起(owner「同一時間只允許同一帳號登入一個位置,登入新位置,自動踢掉舊位置」)。**位置 = 一個瀏覽器**:畫面在 localStorage 產生記號 `mp_pos_device`(`api/client.ts::deviceId()`,規則 `lib/signInPlace.ts`;登出不清),登入帶 `device`。規則只有 `backend/apps/tenants/sign_in.py::sign_in` 一份:鎖帳號那一列;同一個記號拿回原本那一把 token(同一個瀏覽器另開分頁不踢自己);不同記號或沒帶(舊畫面、瀏覽器不給存)→ 舊的刪掉、雜湊記進 `SignedOutElsewhere`(留 14 天)、發新的、記進 `SignInPlace`。驗證(`backup/auth.py`)遇到被踢的那一把回 401 `{detail: 帳號已在別處登入, code: signed_in_elsewhere}`;畫面 401 帶這個 code 時登入頁顯示那一句(`AuthContext` 的 `notice`,登入成功才收),登入後分頁在前面每 60 秒問一次 `/auth/me/`、切回分頁也問。**每個帳號一樣、沒有例外**;登出、改密碼、老闆重設 / 停用照舊刪掉那個帳號的 token(一帳號一把沒變)。兩張表不進公司備份。不做登入紀錄、裝置清單、登入前詢問。測試 `tenants/test_sign_in.py`

### 閒置自動登出

2026-10-12 起**連續 2 小時**沒有操作才登出(owner:「十分鐘太短」;原本 10 分鐘)。門檻與算法只有 `frontend/src/lib/idleLogout.ts` 一份(`IDLE_MS`;`AuthContext.tsx` 只負責接上)。**看實際經過的時間**(電腦睡眠、分頁被凍住也算進去),每分鐘看一次時鐘;滑鼠 / 鍵盤 / 觸控 / 捲動 / 點擊重新算,背景輪詢不算。**掛在 `window` 的 capture**(搶在所有按鈕與其他元件前面):時間內先記一次操作(別的元件把按鍵攔下來也算);超過時間的那一下先清憑證、再整個吃掉(按不到畫面上的東西)。**別的元件不要在事件上用 `stopImmediatePropagation`**(測試會擋)。到期只清這一頁的登入、不呼叫後端登出(憑證是同一個瀏覽器的分頁共用的)。決策見 `docs/decisions.md` 2026-10-12

### 倉別鎖定機制

`apps.core.warehouse_scoping.WarehouseScopedMixin` 套在所有業務 viewset(Sales / SalesReturn / Purchase / PettyExpense / CashAdjustment / PhoneBillCollection),依 `is_warehouse_locked` 自動 filter queryset + 建單時驗證 warehouse。Transfer 用 `TransferWarehouseScopedMixin`(from OR to 是自己倉就算自己的單,建單時 from 必須是自己倉,confirm action 要求 to 是自己倉)。`business_daily_report` API 直接擋非自己倉的請求

### 經手人預設

前端 `useDefaultHandledBy()` hook 從 `request.user.sales_person`(`SalesPerson.user` OneToOne)取當前登入者的業務員,form 開啟時自動帶到 handled_by。Drawer 表單(雜支/現金調整/代收話費)+ 銷貨 entry page(sales_person)都有套

### 平台後台

`/platform/tenants/` / `/platform/users/` / `/platform/warehouses/` CRUD,permission `IsPlatformAdmin`。前端 PlatformAdminPage(/platform/admin,3 tabs)只有 platform_admin 看得到 nav 入口。建用戶時可勾「同步建立業務員主檔」+ 指定 sales_person_code,一鍵建好 User + UserProfile + SalesPerson

### 門市資訊

`Warehouse` 加 `address` / `phone` 欄位;在 SettingsPage「門市」區塊 inline 編輯(blur 即存)。代碼/名稱仍鎖死,只能改地址/電話/啟用。資料用於收據抬頭

### 關聯欄位只認自己公司

`apps/core/tenant_fields.py` 的 `TenantScopedRelatedFieldsMixin`:序列化器(含巢狀明細)的外鍵欄位限縮到 `request.tenant`,猜到別家編號會被欄位本身擋下。**所有 app 的 serializers.py 每一個序列化器都要掛**(平台後台 `tenants/platform_views.py` 例外,它本來就跨公司);`apps/core/test_tenant_fields.py` 會掃全部序列化器,漏掛就紅。用原始編號的輸入(ListField / DictField,例如維修的 `parts_input`)mixin 管不到,要自己對公司驗證。service 另外再核對一次(`same_company()`:銷貨、銷退、進貨、調撥、維修完工)。有門市鎖的 viewset 覆寫 `perform_create` 時**要自己呼叫 `check_create_warehouse()`**(同一支測試會檢查),否則鎖倉店員能在別家門市建單

### 不靠送編號也不能看到別家

API 只回 JSON(`DEFAULT_RENDERER_CLASSES`):DRF 的 API 瀏覽頁(`?format=api`)會把篩選與表單下拉整張表列出來,**不可再打開**。外鍵篩選(`?customer=` …)走 `apps/core/tenant_filters.py` 的 `TenantDjangoFilterBackend`,別家編號跟不存在的編號一樣回 400。指向帳號表的 `created_by` 一律唯讀(由 view 設定)。沒綁公司的帳號只有 platform_admin / superuser 能用 `?tenant=` / `X-Tenant-ID` 指定公司(`tenants/middleware.py` 的 `may_switch_company`),其他沒綁公司的帳號在登入驗證就 403
