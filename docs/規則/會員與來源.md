## 設計決策

### 客戶來源與會員（2026-10-11）

**客戶來源與會員（2026-10-11）**：Customer 是來源（通路／同業等），Member 是個人或公司。會員來源分沿用銷貨預設／固定直客／指定來源；新銷貨先帶公司預設（未設為直客），選會員帶來源，手選本單不回寫會員、不被換會員覆蓋，不同時提示並可套用。公司會員統編供開票，來源統編不帶入；新單保存來源名稱，舊單不重掛。維修聯絡及返修用實際會員，無會員舊單用原客戶。詳見 `docs/development/CUSTOMER_MEMBER_SOURCES.md`。

## 規則

### 客戶識別

`Customer.code` 系統自動產生 (C-{5 位流水},Tenant 持有 next_customer_seq);前端不顯示也不輸入。`phone` 選填(同行/企業可不填);`lookup?phone=` 多筆回最舊。客戶表只放「歸屬」類型(個人/同業/企業/其他),不再帶會員身分

### 會員主檔(獨立)

`Member` 是獨立 model(M-{5 位流水},Tenant 持有 next_member_seq);欄位姓名/電話/身分證/生日/地址/備註/啟用;前端 `/members` MembersPage CRUD;`searchMembers` / `lookupMember` 走 `/members/` API **名單點一位 = 只在新分頁打開 `/members/編號` 看消費紀錄,原頁維持整頁名單(標出剛看的那一位);那一列最後的「編輯」才在原頁右邊開編輯欄位**(2026-10-20 owner「點會員，自動跳分頁，目前瀏覽視窗太小了」「跳分頁只要顯示消費紀錄不要編輯會員資料，原來的頁面右邊只需顯示編輯欄位」;2026-10-23 改:點名字同時開右邊,回到原頁版面變成左右兩欄他覺得奇怪,選「清單一直整頁」;`lib/memberUrl.ts`):新分頁是 `MemberHistoryPage`(整頁寬、分頁標題寫會員名字;購買明細 + 舊系統紀錄,沒有可以改的格子;**2026-10-24 全站檢視 E3**:新系統還沒有消費就不列那張空表、直接看舊系統那一段,兩邊都沒有才寫「沒有消費紀錄」;舊系統那一段單別寫銷貨 / 退貨(`lib/legacyHistory.ts::docKind`,E 開頭銷貨、F 開頭退貨)、只留淨額一個金額、篩選只留日期與品名、待核只給管理員看不用紅色,叫法一律「舊系統」);原頁右邊只有編輯欄位。**消費紀錄只開一個分頁**(同一天「不要自動跳轉過去，一樣留在原始頁面」;`showMemberHistory`):瀏覽器不讓網頁在背景開新分頁,所以第一次開(會切過去),之後點別位是那個分頁在背後換人、留在原頁;**不要改回每點一位 `window.open` 一次**(每次都會切過去)。**消費紀錄分頁只看、不套外框**(2026-10-21 owner「不用有側邊欄，也不需要有客戶…讓分頁無需有任何功能」):`isMemberHistoryPath` 讓 App 當它是 `?focus=1`(沒有側邊欄、上面那排),點一列不跳銷貨單;舊 POS「確認對照」在原頁右邊(`LegacyLinkCandidates`,管理員),消費紀錄分頁不放任何按鈕。

### 舊系統消費紀錄

`LegacyPurchase`(sales app)輕量表,只記「member / product / qty / unit_price / doc_date / source_no」;CSV 經 `manage.py import_legacy_purchases` 灌入;不還原成 SalesOrder。MembersPage 與現役單合併排序顯示(舊資料加「舊」徽章),`last-price` API 兩邊都查、取較新

### 全站用語

2026-10-23 起(全站檢視 G3,owner「照你建議」;**只改畫面上的字,資料、欄位名稱不動**):**客人一律叫「會員」、通路同業叫「來源」(客戶 → 來源;沒有來源 = 直客)、進貨對象叫「廠商」(供應商 → 廠商)、店一律叫「門市」(分店、入庫倉、出貨倉、倉別 → 門市)**。「會員來源」入口(原「客戶會員」)一進來先到會員、「客戶」分頁叫「來源」、來源清單沒有「個人(舊類別)」那一頁(那些照樣在「全部」);「供應商」分頁叫「廠商資料」;「客戶排行」叫「來源排行」;舊的叫法都留在 `nav.ts` 的 `aliases`(功能搜尋打得到)。單據 / 報表 / 匯出的欄名一起改(銷貨日報匯出的前 14 欄欄名也改了:出貨倉 → 門市、客戶 → 來源);沒有來源的單寫「直客」、沒有會員寫「非會員」;維修單上的「客戶」是那個人 → 會員,「客戶實付」→ 實付。**不改的**:商品的「倉別」(商品倉 / 零件倉,不是店);維修收據上印好的條款文字(「如客戶要求…」「客戶聯」「客戶簽名」,要不要改問 owner);滑鼠提示裡口語的「客人」;後端只給工程師看的訊息。
