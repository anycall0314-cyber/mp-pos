## 規則

### 發票自動取號

銷貨單儲存時,依 `invoice_form` 從 `InvoiceTrack` 字軌 `SELECT FOR UPDATE` 取下一張號碼,寫入 `invoice_no`(一張單一個號碼)。**2026-10-13 起(PR1 發票第一批 I1;owner:發票機是 WP-103、紙是號碼已經印好的整捲三聯式 ——「要可以設定發票字軌…還要可以設定跳號指定幾號開始印製」「字軌設定不但有指定年月與字軌數字，跳月如未設定…則自動提示」)**:**一條字軌是一間門市、一期的**(`warehouse`;`period_start` = 那一期的第一天,兩個月一期,`tenants/invoice_periods.py`)。取號(`tenants/services.py::assign_invoice_no(tenant, code, warehouse_id, day)`)只取**這間門市、發票日期那一期**的字軌:自己門市的先、全公司共用的(`warehouse` 空的 = 分門市之前建的舊字軌)後;有登記期別的先、沒登記的舊字軌(不分期)後;別間門市、別期的不拿。取不到 → 結帳被擋,訊息講是哪一期「還沒設定 / 用完了」。新增字軌一定要選門市與期別(`period_label` 由 `InvoiceTrack.save` 照期別填)。**「下一張」只有新增時可以填,之後只能跳號**:`POST invoice-tracks/{id}/jump/ {next_number, reason}`(`jump_invoice_track`)—— 填的是發票機裡那捲紙的下一張;可以往後(中間幾號不開了;跳到迄號 + 1 = 這一捲不用了)、也可以往回(改打錯的),**條件只有一個:新的下一張與它後面的號碼都還沒有寫在任何銷貨單上**(`issued_numbers`:看銷貨單上的字,作廢的單、自己打的號碼、大小寫不同的都算);先鎖字軌那一列再查(開單取號鎖同一列、鎖到那張單存完)。**另外不能跳到系統開出去過的號碼前面**(`InvoiceTrack.floor_number` = 開過的最大號碼的下一號,取號時往前推、跳號不動它;備份還原時 `next_number`、`floor_number`、`range_end` 都只取大的(`backup/registry.py::HIGH_WATER`)—— 回到較早的備份之後那張單不見了,號碼也不能再開;備份之後加長的迄號不縮回去(縮回去的話那一段可以被另一條新字軌拿去重開))。每一次留一筆 `InvoiceTrackJump`(原本 / 改成 / 原因 / 誰;`GET invoice-tracks/{id}/jumps/`)。開過發票或跳過號的字軌不能刪、字軌兩碼 / 起號 / 類型不能改,迄號不能縮到已經用到的前面;同一家公司兩條字軌的號碼不能重疊。**新增 / 修改 / 刪除字軌都在交易裡**:新增與修改先拿「這家公司在動字軌設定」的諮詢鎖(`services.lock_track_setup`;重疊是先查再寫,排隊才看得到同時在新增的另一條),修改與刪除再鎖字軌那一列**重新讀**(`InvoiceTrackViewSet.get_object`;不然存檔會把剛被結帳取走的「下一張」蓋回舊的)。鎖的順序:先公司那一把、後字軌那一列;開單取號與跳號只鎖字軌那一列。**權限 `invoice_tracks`「發票字軌」**(新增 / 修改 / 刪除 / 跳號;看與預覽不用)。鎖在門市的帳號只看得到自己門市的與共用的、只能動自己門市的(共用的只能跳號)。`GET invoice-tracks/peek/?invoice_type_code&warehouse` 回下一張、是哪一條字軌(`track`)、取不到的原因(`detail`),以及**這一期最後 7 天、下一期還沒設定時下一期的名稱(`upcoming`;沒登記期別的舊字軌不提醒)**。畫面:系統設定的字軌表單(門市、年度 + 月份)與清單的狀態(使用中 / 已停用 / 已過期 / 已用完 / 未開始;規則 `lib/invoiceTracks.ts`);跳號視窗 `components/invoice/InvoiceJumpDialog`(系統設定與開單頁的發票號碼旁邊開同一個;按確定之前先寫出跳過哪幾號、或往回幾張)。備份:`InvoiceTrackJump` 是公司資料;備份之後才設的字軌還原時門市照代碼對回去(對不回來就停用,不會變成共用)。**還沒做(I2,等 owner 給發票機接線照片與樣張)**:印到 WP-103、發票上的品名(照銷貨品名 / 自己打)、印壞那一張換號重印;一張單印不下怎麼辦

### 發票機(WP-103)測試頁

2026-10-13 起(PR1 發票第二批的第一步;owner:三聯式收銀機發票是過渡用的、之後走電子發票串接 → **只做最簡單夠用的**)。發票機接 USB、Windows 認成 COM 埠(`Prolific USB-to-Serial`);**伺服器把一頁排好、轉成位元組,接發票機的那台電腦用 Chrome 的 Web Serial 原樣送進 COM 埠**(不用驅動)。排版與位元組只有 `backend/apps/sales/wp103.py` 一份:一行最多 39 格(中文一個字 2 格)、一頁 33 行、BIG-5(機器沒有的字印成 `?`、資料裡的控制字元變空白)、`ESC @` + `ESC C 33` + 每行 `LF` + `FF`;**每一項在第幾行(`ROWS`)、從第幾格開始(`COLS_AT`)是從樣張的照片量的,還沒有在實機上對過** —— 紙上印好「日期:」「買受人:」「銷售額:」「營業稅:」「總 計:」,機器要對著印。品名或付款方式排不進一頁就丟 `LayoutError`(不默默少印)。`GET invoice-printer/test/?kind=ruler|sample&top=`(`sales/invoice_printer.py`)回排好的每一行與 base64 的位元組;不碰單據、不取號。畫面 `/settings/invoice-printer`(系統設定 →「發票機台」,跟著權限 `invoice_tracks`;`pages/settings/InvoicePrinterPage.tsx`、`lib/serialPrinter.ts`):選埠(要在按鈕的點擊裡)、速率、行號測試、樣張測試、上面空幾行;速率與空幾行記在那台電腦的瀏覽器(`mp_pos_invoice_printer`);每印一次開關一次埠(不佔著)。門市照著做的步驟在 `docs/發票機_WP-103_測試步驟.md`。**還沒做**:開單之後印真的發票(品名照銷貨 / 自己打、賣方統編與收銀機編號的欄位、照號碼順序印、印壞換號重印)

### 發票明細

2026-10-12 起(取舊歐睿 FI012 開立發票表)。`GET sales-invoice-report/?from&to&by&warehouse&form&state&search&page&export=1`(`sales/invoice_report.py`,只讀;頁面 `/reports/invoice-detail`):**有發票號碼的銷貨單一張一列、照號碼排**(免用發票、沒有號碼的不列);日期看發票日期,沒填(自己打號碼的)看單據日期。**狀態**:`void` 作廢 = 銷貨單整張作廢,或 `invoice_voided` 而且沒作廢的銷退金額 = 發票金額(銷退只能整張退;建立銷退時「作廢原發票」預設是勾的);`check` **待查** = `invoice_voided` 但金額對不上 —— 實際上就是那張銷退後來又作廢了(`void_sales_return` 不會把記號拿掉):貨沒有退、發票卻記成作廢,單獨列出來讓店裡處理;其餘 `ok` 正常(有退但沒作廢原發票的也是)。**合計的金額只算正常那幾張的發票面額(沒有扣銷退)**;作廢幾張、待查幾張與金額、正常那幾張被退的金額各自一格。`by=return` 照銷退日:列出期間內有銷退的發票(不管哪一期開的)、「銷退」是那段期間退的 —— 上一期開的發票這一期才退,照發票日看這一期的表上沒有它。**作廢日(2026-10-12,owner「作廢要日期」)**:銷貨單作廢的當下系統自己記 `SalesOrder.voided_at`(哪一刻)與 `voided_by`(誰按的)—— `void_sales_order(so, user)`,不收人填的時間、不記原因、作廢被拒絕什麼都不記;有這兩欄之前就作廢的單是空的。銷貨單的回應帶 `voided_at`、`voided_by_name`(唯讀),銷貨單清單在「已作廢」旁邊寫時間與帳號(`lib/voidStamp.ts`)。發票明細每一列多 `void_date`:銷貨單作廢 = 作廢那一刻在系統時區的日期(`TruncDate`,台灣凌晨作廢的算當天),銷退時作廢原發票 = 那張銷退的日期,待查與正常的是空的;`by=void` 照作廢日:列出期間內作廢的發票(不管哪一期開的;沒記到時間的舊單只在照發票日看得到);合計多 `void_total`(作廢那幾張的面額)。**報表怎麼算沒有變**:作廢的單照舊整張不算、算在原本開單那一天。只有銷貨單記;別種單據的作廢還沒有記時間。下拉的選項與字(`choices`)由伺服器給。權限 `report_invoices`(沒有列進 `ALSO_NEEDS`:自訂分析組不出逐張的表);鎖在門市的帳號只看自己門市。加總時名字不能跟欄位同名(`Sum("total")` 取名 `total` 之後,同一次加總後面的 `Sum("total")` 會被當成前一個的結果而報錯)。不做:折讓單、進項發票、跟財政部平台核對、跳號 / 重號檢查、依課稅別小計。 **開立發票彙總表(2026-10-20;owner:「我每個單數月，要傳發票開立明細彙總表excel給會計師報帳」)**:同一頁「匯出明細 / 匯出彙總」,「上期」帶剛結束的那一期(兩個月);`GET sales-invoice-summary/?from&to&warehouse&form`(`invoice_report.summary`,同一項權限、鎖門市只算自己那一家)。照舊歐睿 FI012 彙總的欄位:上段 = 期間內(發票日)有號碼的銷貨單,同一天 × 門市 × 發票類型 × 字軌(號碼前兩碼)一列、號碼寫當天第一張 ~ 最後一張,**作廢的單也算**(號碼用掉了);下段「作廢與退回」一張一列負數 = 期間內(退的那一天)沒作廢的銷退(作廢原發票「退貨作廢」/ 沒有「退貨折讓」)+ 期間內(作廢那一天;沒記時間的舊單看發票日)作廢的銷貨單「銷貨作廢」;總計 = 上 + 下。金額是發票面額。一張發票只扣一次(有有效銷退的單不能作廢)。檔的排法 `lib/invoiceList.ts` 的 `summaryTable`。**系統還沒開始印發票之前,這一份不能拿去報稅**(紅隊)。
