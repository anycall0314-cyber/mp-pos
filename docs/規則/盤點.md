### 盤點作業

2026-10-12(owner 定的三條:**差異要管理員調整與核准、帶序號的逐台刷、盤點中可以繼續開單**)。規則 `inventory/stockcount.py`,端點 `inventory/stockcount_views.py`(`stock-counts/…`),頁面 `/inventory/stocktake`、`/inventory/stocktake/:id`。**盤點單** `StockCount`:一家門市(可以只盤幾個類別 `StockCountCategory`;沒有 = 全部),盤點中 → 待核准 → 已核准 / 已作廢;同一家門市同時只有一張還沒結束的(部分唯一限制);單號 `SC-000001` 各公司自己編。**盤的人只記數到的,庫存一個數字都不動**:配件 `StockCountLine`(數到幾個 + **輸入那一刻**的帳上數量;重新輸入 = 換掉並重記);手機 `StockCountScan` 逐台刷(記下刷的那一刻那一台帳上是不是就在這家門市)。**配件那一格是工作台的掃碼框(`ScanBox`,2026-10-15)**:條碼槍刷舊貼紙(舊品號 = 條碼)或品號,完全相同剛好一個才直接選(`lib/stockCount.ts` 的 `sameCode`)、選好游標跳到數量(這張單記過的先放原本的數);刷了沒選到的記在「沒加入」;**選了還沒記下時又刷到別的,那一個記在「沒加入」、不蓋掉**(`pickProblem`;複審 P1:條碼槍連刷兩張、搜尋還沒回來);還有沒加入的碼、或選了還沒記下,不能送出(送出要等掃碼框排隊的處理完、讀**當下**選著的 `accessoryNow`,不是按下去那一刻畫面上的 —— 複審 P1)。**不可以換回一般下拉(`ComboBox`)**:點進去會先載入預設清單,條碼槍比搜尋快、Enter 會選到清單第一個(本機實測選錯過)。**電腦的手機那一格也是工作台的掃碼框、只收碼**(2026-10-23 全站檢視 B6:`ScanBox` 的 `menu={false}`,刷完立刻清空、連刷排隊、沒刷進的記在「沒加入」、送出前要處理;以前是一般輸入框,下一槍會接在上一槍後面)。核准的售價收成整數元(成本照舊到分)。**手機走動盤點(2026-10-15,owner「盤點要有手機可以配對掃，方便走動盤點」)**:盤點單按「手機盤點」寫稱呼、產生 QR Code(一支手機一個,最多同時 10 支);手機開 `/m/count#憑證`,**不登入**,跟商品照片同一套(憑證只存雜湊、3 分鐘沒掃失效、綁第一支掃的手機、30 分鐘沒刷 / 12 小時結束、每個動作先鎖盤點單再鎖配對那一列核對;規則 `inventory/stockcount_phone.py`,表 `StockCountPhone`、`StockCountOp` 不進公司備份、還原時清掉)。刷到配件的品號 / 條碼(含已確認的條碼別名)→ **+1**(`stockcount.add_to_line`,鎖那個商品在這家門市的餘額列排隊,兩條連線的測試);機器的碼 → 記那一台(`scan`);都不是:「配件」模式記成**沒對到的碼** `StockCountUnknown`(電腦指定配件 = 刷幾次加幾個,或寫原因不入;**還有沒處理的不能送出**),「手機」模式當一台手機(第一次入庫)。「這一堆幾個」把最後那一下改成 +N、「收回這一下」減回去:加減不會互相蓋掉,**那一下之後電腦整格換過(`StockCountLine.replaced_at`)就擋**;減到 0 而且電腦沒打過 → 整列拿掉(回到沒盤)。**電腦打「數到幾個」要帶 `seen`(選到那一刻看到的數字),跟現在不一樣就擋**(紅隊:不能默默蓋掉手機加的)。每一下記在 `StockCountTap`(稱呼、加在哪一列 `line_ref`、從幾個變幾個;記配對編號不記外鍵)—— **那一列被移除、重建過,舊的那一下就收不回**(複審 P0)。**手機每個動作帶自己的編號 `op`,`StockCountOp` 記做過的,同一個編號重送不再做**(複審 P0:回應在路上斷線、重刷多 +1);手機斷線(含伺服器回 200、內容沒傳完)自動用同一個編號重送三次,還不行列成「還沒確定 N 下」按重送 —— **有還沒確定的動作時,後面刷的都排在它後面、不會先送**(複審第二輪 P0:收回會被超車、收到別的那一下);「收回 / 這一堆幾個」帶手機看到的最後一下(`target`),伺服器的最後一下不是它就擋。**送出 / 作廢時手機一律結束**(退回重盤要重新產生 QR Code;複審 P1)。手機看狀態只鎖配對那一列(`select_for_update(of=("self",))`;連帶鎖盤點單會跟刷碼互等卡死,複審 P1)。**電腦上的「已配對 N 台」(2026-10-24 全站檢視 V06b)**:手機那一頁每 10 秒回報一次(`StockCountPhone.seen_at`;刷碼也算),30 秒沒回報 = 斷線 `lost`(只是顯示,回來照樣能刷、還佔名額);N 只算連著的,電腦 15 秒沒抓到新的盤點單寫「連線中斷」,重抓失敗不整頁換成錯誤;剛發的 QR Code 被掃了才收起來,按鈕永遠叫「手機盤點」(手機上的訊息叫人按這個)。資料庫變更 `inventory.0022`。手機看得到自己刷了什麼與那個品項大家合起來數到幾個,**看不到帳上數量**。盤點單有手機在等掃 / 連著時每 4 秒重抓。相機:Android 的 Chrome 用內建的 BarcodeDetector,其他(iPhone)用 `barcode-detector`(ponyfill,zxing-wasm)—— **讀條碼的 wasm 要用 `?url` 打包、`locateFile` 指到自己網站**(預設會去 jsDelivr 抓);相機一直對著同一個碼只算一下,**同一個碼看不到 450 毫秒再出現才算下一下、兩下至少隔 700 毫秒**(`lib/phoneCount.ts` 的 `createScanGate`;假鏡頭實測:有這條 +2、拿掉 +29)。資料庫變更 `inventory.0018`。不鎖庫存:差異 = 數到的 − 當時帳上的,之後賣掉 / 進貨的是正常的異動;**核准時是「現在的帳上數量 加減 調整量」**,不是改成數到的數字;不夠扣就整張不動、講是哪一個商品。手機少了哪幾台在**送出時**算(`StockCountMissing`):帳上在這家門市在庫、沒刷到、而且不是盤點開始之後才進來的 —— **要送出的人表明「手機全部刷完了」(`phones_done`)才算**,沒有表明 = 沒刷到的是「沒盤」;核准的當下已經不在庫的(賣掉、調走)不標。刷到但當時帳上不是這家門市在庫的(已售、別家、不認得)= 多的:**只列出來,不自動處理**。**核准(只有管理員)才動庫存**:每一列可以改調整量、先不調、寫原因;配件照調整量加減、記一筆「盤點調整」異動(增加寫 `to_warehouse`、減少寫 `from_warehouse` —— 每日對帳的「庫存 = 異動加總」靠這個;平均成本不變,這家門市從來沒有過的用公司的平均成本);少的手機改成新的序號狀態 **`lost` 盤虧**(不算在庫、不能賣、**還佔著碼**,跟作廢不一樣);之後找到了管理員按「找回」→ 回到在庫、記一筆異動。核准之後不能作廢、不能改。**盲盤**:帳上數量、差異、金額、哪幾台少了 / 庫存餘額**(跟銷貨同一個順序;讀餘額的查詢照品號排序、會連帶鎖住商品那一列。**核准時不可以另外「先鎖商品」**:那樣會跟銷貨相反,同一張銷貨單有那一台手機與那個配件、又同時核准時會死結 —— 複審第二輪抓到的 P1;有兩條連線的測試)。**複審抓到、寫的時候要記得的三件事**:(1) 讀帳上數量要 `locked_balance(create=True)` ——
