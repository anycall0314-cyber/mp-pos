## 規則

### 中古機

`Product.is_secondhand=True`;`ProductSerial` 逐隻記 `condition_grade` (S/A/B/C/D)、`custom_unit_price`、`battery_health`、`condition_note`;銷貨選機自動帶 `custom_unit_price`

### 逐台記機況 ≠ 中古機

`Condition.tracks_unit_condition` 決定進貨要不要逐台記 成色/電池/個別售價/備註;**已拆封不是中古機但一樣要記**。`Product.tracks_unit_condition` property:中古機一律 True,否則看品況,舊資料(condition=NULL)退回 `is_secondhand`。**每隻獨立成本仍只看 `is_secondhand`**,成本政策不跟著放寬。DB CheckConstraint 擋掉「中古機 + 不逐台記」

### 商品品況

`Product.condition` FK → `Condition`(全新 / 已拆封 / 中古機…)。serializer **唯讀**輸出 `condition` / `condition_name` / `tracks_unit_condition`;改品況要走逐台重分類,不能直接改主檔把同 SKU 的其他新機一起變掉

### 中古機類別連動

`Category.is_secondhand_default=True` 時,該類別下所有 product `is_secondhand` 自動帶 True(`Product.save` override)。類別 default 由 False → True 儲存時,cascade 把底下所有商品 `is_secondhand/requires_serial` 設 True、`is_virtual` 設 False;反向(True → False)不 cascade,避免誤改既有資料。前端 ProductsPage 的類別新增/編輯 form 多一個「中古機類別」勾選

### 個人收購

「中古入庫」頁的「個人收購」tab(`SecondhandPersonalEntry`);走 `acquire_secondhand_from_member` service:同 transaction 建中古機序號 + 對應銷貨單(虛擬商品「收購二手」、`untaxed`、total 負數代表現金流出);**來源一律直客**(SO.customer 空、`source_name`「直客」;2026-10-23 起,全站檢視 E1 —— 以前照會員電話自動建一筆 individual `Customer`,來源清單多出一堆跟會員同名的「個人(舊類別)」;舊單不改寫),SO.member 記賣機的人(營業日報「收購現金支出」那一列看 `member_name`);serial 反向掛 `acquired_from_member`(指 Member)+ `acquired_via_sales_order`。**收購價算進商品的平均成本**(2026-10-30,owner:「整理後,平均成本、總成本都只有維修成本,沒有含收購成本」):先鎖商品,照進貨同一個算法 (全公司在庫台數 × 現在的平均 + 收購價)÷(台數 + 1);以前只記在那一台上,舊資料由 `inventory` 0024 把收購過的品號重算一次(現在算平均成本那幾台的成本平均,一台都沒有的不動)。測試 `sales/test_buyback_cost.py`。**作廢收購單,收進來的那一台一起作廢**(2026-10-30,owner「可以」;以前錢退回去了機器還在庫存;`sales.services._void_bought_units`):先鎖商品與那一台(連同可能接手它的碼的設備),收進來之後沒動過才可以 —— 在收購的門市、在庫、除了收購入庫沒有別的異動(賣過再退回、調撥、整理過(含開了又取消)、換貨過都不行)、沒有被同行訂著;那一台 void、釋放碼(可以重新收購)、寫一筆「收購作廢」(從收購的門市扣,進銷存表沖回進貨欄);商品平均成本跟進貨單作廢一樣用剩下那幾台重算

### 廠商收購中古

「中古收購」頁的「廠商收購」tab,內嵌 `PurchaseWorkbenchPage mode="secondhand-vendor"`(進貨的工作台);走一般進貨單流程但商品搜尋限定 `is_secondhand=true`;每一台在那一行底下多成色 / 成本 / 售價 / 電池 / 備註 +「套到下面」;存完不離頁。**Excel 大量進貨(2026-10-14,owner:「中古機我希望可以用Excel匯入的方式大量進貨」)**:工具列多「匯入表格」(只有這一頁)→「下載範本」(`GET secondhand-purchase-sheet/`,系統當下產生:一列一台 品名 / IMEI / 序號 / 成色 / 電池 / 進價 / 售價 / 備註,IMEI 與序號欄設成文字、成色下拉,附「品名」= 這家公司啟用中的中古機品號,品名可以選也可以貼廠商的寫法)→「選擇檔案」(要先選廠商與門市;`POST` 只讀:每一格的問題、品名對到哪個品號、碼在不在系統裡,規則 `purchasing/secondhand_sheet.py`)→ 預覽 →「加入 N 台」變成這張單的明細(一個品號一行、每一台自己的成本 = 進價,存檔時含稅照原本的規則除 1.05)、按儲存才成立。**動手前紅隊三條**:(1) 品名**只認確定的**(一字不差的品名、品號、條碼、記住過的已確認叫法;廠商自己的叫法只算那家廠商),像但不確定的**不先帶**,一個品名人自己挑一次、可以勾「記住」(下次直接對到);(2) 碼已經在系統裡的那一台不能加(賣出去過的也一樣 —— 收回來的功能另外排),檔案裡重複的標出來;(3) 預覽第一行寫進哪家店、哪家廠商、課稅別,成本照稅別顯示。**複審第一輪兩個 P0**:成色、進價一定要填、**進價要大於 0**(每一台成本是 0 時存檔會改用那一行的單價 —— `services._serial_cost`);**換了廠商,讀過的那一份整個作廢**(品名照那家廠商的叫法對的),讀檔途中換的晚回來也不要;匯入的不因為那一行的單價跟明細裡不一樣被擋。同一批修了「批次貼上」:從 Excel 複製的(Tab 分隔)只認第四格是序號,後面的欄(成色、售價…)不再被當成序號;中古機的範例只留讀得到的欄
