## 規則

### 店頭雜支

`PettyExpense` 記每家門市的零星支出(房租/水電/餐飲/雜物/其他);自動單號 `EX-{5位}`;`payment_method` FK 預設現金。Phase 1 純記錄,Phase 2 將連動 `Warehouse.cash_balance`。**雜支與現金調整存好就不能修改**(owner 2026-10-24:「記錯只能作廢再重記」;改了不留紀錄、會改到過去的營業日報):伺服器 `update`(PUT / PATCH)一律 405、畫面沒有「編輯」、表單只能新增;作廢照舊要「作廢其他單」。`cash/test_no_edit.py` 會擋

### 代收話費

`PhoneBillCollection`(cash app)記店家代收客戶繳的電信費;單號 `PB-{5位}`;欄位 carrier/phone_no/amount/id_no/handled_by(全必填)+ member 選填(輸入電話自動 lookupMember,找不到可現場新增會員或略過)。**儲存即生效、現金收入**,進入營業日報「收入區 → 代收話費」與現金櫃流水「代收話費」格(算正向加入今日結餘)。**不開發票**(代收性質),只有 80mm 熱感收據:**店家抬頭(門市名/地址/電話)** + 單號/日期/電信/完整電話/隱碼身分證/金額。身分證隱碼規則 `頭3 + ***...*** + 末1`(`pages/phone-bills/mask.ts`)。作廢用 `POST /phone-bills/{id}/void/`。**記一筆一步存**(2026-10-24 全站檢視 E8):雜支 / 現金調整「儲存」、代收話費「儲存並列印」(存好直接開收據;視窗被擋寫「收據沒跳出來」留「再印收據」),沒有確認頁、按 Enter 不存、連按兩下只送一次;雜支與代收話費存完表單留著、上方一條「已存 …」+ 兩段式作廢(`components/SavedStrip`),雜支的付款方式回到現金、經手人回到登入的人;現金調整存完就關、訊息寫事由與存入 / 提取。代收話費的電信業者是一排小標籤(業者清單來)、記住這台電腦上次選的,一打開游標在電話

### 維修收款與營業日報、現金調整方向

2026-10-23 起(全站檢視 E5~E7;owner「維修現金進營業日報」要)。`RepairOrder.payment_method`(`repairs.0008`,可空的 FK 到付款方式)。**客戶實付大於 0 要先選收款方式才能完成**(`services.complete_repair_order`,伺服器擋;畫面沒有預設、要人選 —— 紅隊:預設現金會讓刷卡的被算進現金)。開單頁按「完成」先存檔再完成(`submitGate` 擋連按;以前按完成不會存剛改的實付);已完成 / 作廢的單整區唯讀(`fieldset.re-lock`)。**營業日報的「維修現金」**:那個門市、已完成、沒作廢、收款方式是現金(`kind=cash`)的維修單,**算在完成那一天**(`completed_at`,店裡的時區),金額 = 客戶實付;進當天結餘,前幾天的進期初(`cash/views.py::_repairs_paid_in_cash` 一份,兩處共用)。沒填收款方式的舊單、刷卡 / 轉帳的不算;重開再完成換到新的那一天。格子叫「維修現金」不叫收入(只代表進櫃子的錢;維修業績看維修月報)。**現金調整的事由決定方向**(`CashAdjustment.REASON_DIRECTION`):補零用金 = 存入,存銀行、老闆取用 = 提取,伺服器擋(`CashAdjustmentSerializer.validate`,改既有的也擋);盤點校正、其他兩個方向都可以。畫面事由放第一格、選了固定方向的那一格鎖住(`lib/cashAdjust.ts`)。**打烊實點**(2026-10-23,owner「實點加上去」;`cash.CashCount`,`POST reports/business-daily/count/ {warehouse, counted}`):營業日報「打烊實點」卡片打進點到多少 → 記下點到、那一刻系統算的應有現金(= 明天的期初,`_compute_cash_balance_before(明天)`)、點的人(業務員名字,沒有用帳號);**不改帳**(今日結餘、隔天期初照舊,要補帳另外開現金調整);一天可以點好幾次、**每一次都列**(紅隊:早班的短少不能被晚班蓋掉)、點過不能改不能刪;只有今天能點(`can_count`);看得到營業日報的人才能點、鎖在門市的只能點自己門市;寫「點的人」不寫成短少算誰的(紅隊:沒有班表);同一張卡片列出這一天的現金調整(事由、金額;紅隊:補平的要看得到)。
