## 規則

### 同一份建單只成立一次

進貨單、銷貨單的建單端點認得 `Idempotency-Key`(`apps/core/idempotency.py` 的 `IdempotentCreateMixin`,紀錄在 `core.IdempotencyKey`):畫面每開一張新單自己產生一把鑰匙,送出時帶著;連線中斷不知道有沒有成立時拿同一把再送 —— 已經成立就回那一張(HTTP 200、`Idempotent-Replay: true`),不會開第二張、不會收兩次錢。第一次被擋(4xx)鑰匙不會留下,改一改用同一把再送是一次新的建單。鑰匙記的是單號(還原備份後編號會換、單號不會),只留 7 天,不進公司備份。沒帶鑰匙的請求跟以前一樣。工作台的送出規則:4xx = 沒成立;斷線 / 5xx = 不知道 → 整張單鎖住,只能「再送一次」(同一把鑰匙)或「取消」。**鑰匙、「送出去了還不知道結果」、付款方式都跟著草稿存**(sessionStorage):重新整理或切到別頁再回來還是同一把、而且鎖著;放棄之後不給復原(放回來再送會用新鑰匙)。同一把鑰匙送回來的是已作廢的單 → 講出來、明細留著、換新鑰匙。新的建單端點要防重複就把 mixin 放在繼承清單最前面、填 `idempotency_scope`(調撥與個人收購還沒接)

### 結帳

銷貨單 N 筆 `SalesOrderPayment`(現金/匯款/非現金),`sum(amount) == total` 才能存

### 預設值連動

**開單選了發票類型,課稅別照那種發票的「帶入課稅別」帶**(`InvoiceType.tax_method`,`tenants.0023`;空的 = 不動;既有與新公司的「免用」帶未稅 = 以前的意思,業務設定的發票類型表可以改 —— 2026-10-23 owner:手機玩家發票在舊系統開、稅有繳,免用要帶應稅內含;紅隊:不改「免用」的定義);選商品 → 進貨單帶上次進價 / 銷貨單帶 list_price。開單的會員格、卡號格 Enter 要等現在打的字的結果回來,沒動過上下鍵只選完全相同的(`ComboBox` 的 `exactOnEnter`、`lib/exactPick.ts`);選好會員游標回刷碼框;找不到可以「新增會員」(打的電話帶進去,`memberPrefill`)

### 上次成交價自動帶

`GET /api/v1/sales-orders/last-price/?member=X&product=Y`:跨 `SalesOrderItem`(未作廢、unit_price>0)+ `LegacyPurchase`(unit_price>0)取最近;銷貨建單時新增明細自動帶價,並在單價下顯示「前次 $XXX (日期)」

### 銷貨單客戶/會員雙欄位

`SalesOrder.member` FK→`Member`(獨立主檔),ComboBox 吃電話/姓名/身分證,選填。`SalesOrder.customer` FK→`Customer` = 這筆生意的**來源**(2026-10-11 起;空 = 直客,見上面「客戶來源與會員」)。**不互斥**——同行帶會員來開門號 → customer=同行、member=該會員;會員自己來 → 直客、member=該會員。「個人(舊類別)」的來源只留給舊單,新的單、會員的預設來源選不到(`lib/customerSources.ts` 的 `pickableSource`,2026-10-23 紅隊)

### 銷貨商品搜尋

`searchProductsForSales` 支援 品名 / 品號 / 條碼 / IMEI 任一;打 IMEI 命中時 matched_serial 也預掛該行,且該倉只有 1 隻在庫時自動掛唯一序號(中古機同步帶 custom_unit_price)

### 銷貨可選清單

`?sales_pickable=true` 過濾:庫存 > 0 OR `is_virtual=True`(虛擬商品永遠可選,實體 0 庫存擋下)

### 逐台定價一列一台

銷貨時 `tracks_unit_condition` 的商品數量鎖 1、不併列。同列兩台會用第一台單價乘數量(16000+18000 只收 32000);價格是「那一台」的:選台 / 換一台帶那一台自己的核定售價(沒有就用建議售價),把那一台點掉單價回到建議售價;會員歷史成交價不覆蓋該台核定售價(`SalesWorkbenchPage` 的 `toggleUnit` / `addDevice`)

### 手機回補(不計現金、只算毛利)

2026-10-19 起(owner:「計毛利目前用在手機回補」;選「多打一行」「也算進獎金」「只進毛利」)。商品勾掉「計入現金」= 那一行**客人不用付**;明細存檔當下抄到 `SalesOrderItem.counts_cash`(銷退照原行抄到 `SalesReturnItem.counts_cash`,之後改商品不影響已開的單)。存單(`sales/services.py` `commit_sales_order`):只有客人要付的那幾行算 subtotal / 稅 / total / 付款;不用付的存成未稅 = 金額、稅 0;**不計現金的只能是虛擬商品**。報表(`analytics/catalog.py`):`COUNTED` = 計入毛利 **且** 客人要付 → 銷售額不含回補;`backfill` / `return_backfill` 加進毛利、毛利率、業務員毛利、業務員毛利加佣金。每日對帳(`ledger/checks.py`)只加總 `counts_cash=True` 的明細。前端:開單頁 `paidAmountOf`(應收不含、那一行標「不收錢」)、收據不印、銷貨日報 `paidAmount` / `orderPaidAmount`(金額不含、毛利含)。只退一行時回補不跟著(系統只有整張退)。測試 `sales/test_backfill.py`

### 銷退單

`SalesReturn`(SR-{6位})必指定一張原 `SalesOrder`,**只能整張退**(2026-10-04 起):畫面只送原單 / 退款方式 / 是否作廢原發票 / 備註,明細由後端照原單每一行、全部數量、每一台序號帶入(`items` 唯讀)。每行的金額 / 未稅 / 稅額 / 成本與單頭的小計 / 稅額 / 總額**全部照抄原單**(不重算),銷退跟原銷貨單完全對沖。一張銷貨單同時只能有一張有效銷退(退過不能再退,作廢銷退後才能重退);收購單(總額為負)不能退。有有效銷退的銷貨單不能作廢(要先作廢銷退);建立銷退、作廢銷退、作廢銷貨都先鎖原銷貨單那一列。退款方式必須為原單付款方式之一(原單總額 0、沒有付款時不用填)。退回門市 / 客戶 / 會員都唯讀、一律跟原單一樣(鎖倉店員不能退別家門市的銷貨)。存檔時先鎖原銷貨單再檢查。提交時序號 `sold → returned`(已退,不能賣)、warehouse = 原銷貨單的門市(確認可賣才回在庫,見下一列)、配件 `StockBalance.qty +=`;`void_original_invoice=True` 時把 `SalesOrder.invoice_voided` 標 True(冪等)。`GET /sales-returns/returnable/?sales_order=X` 回原單每行 + `returned_by`(已被哪張銷退退過)+ `is_buyback` 供畫面用。`POST /sales-returns/{id}/void/` 作廢銷退單會把序號退回 `sold`、配件再扣回去;退回來的那一台不在那家門市已退(2026-10-23 稍早那一版退的是在庫,也收),或這張銷退之後它有任何異動(確認可賣、送換貨、盤點、再賣又退回來、調走又調回來)就不能作廢 —— 看的是這張銷退那一筆入庫之後有沒有別的異動。畫面的原銷貨單用搜尋挑(`searchSalesOrdersForReturn`),不載整頁清單。舊資料裡的部分退貨照舊保留

### 一般進貨單擋下中古機

`PurchaseWorkbenchPage` 預設 `mode="regular"`,掃碼框 / 勾選商品 / 批次貼上都帶 `is_secondhand=false`;新增進貨單時挑不到中古品(刷到中古機的品號會講「請到中古收購進」,不會當成序號放進格子)。檢視 / 作廢既有中古進貨單走 `/purchases/:id`(進貨單清單頁展開那一張)。**下拉清單也會告訴人「東西在另一個門」**(2026-10-12,交接包 P1;owner 的例子:一般進貨打 `17 256 中古機`):這一頁沒有一筆「打的字都對得上」(比對回來全是 `related`)時,多問一次另一個門,把那邊都對得上的排在最前面、掛小標「中古機」(廠商收購那一頁掛「非中古」)。點了**不會加進這張單**,回同一句「是中古機,請到中古收購進」/「不是中古機,請到進貨單進」(`lib/purchasePrefill.ts` 的 `wrongDoor`;什麼時候問、問不到當成沒有在 `askBothDoors`,有測試)。判斷只看比對那一條的等級 —— 照字面的 `/products/?search=` 一筆都沒中時會改用相似度去找,有結果不代表對得上。刷碼的判斷(`onScan`)仍只看這一頁的商品(`searchHere`)。

### 進貨付款方式

`PurchaseOrder.payment_method` FK to PaymentMethod (選填);cash 將從店頭備用金扣、transfer/non_cash 不動店頭。Phase 1 只記錄欄位

### 建好品號 → 進貨

2026-10-07 起(owner:「商品管理放在進貨那裡比較合適,建立品號後按進貨」)。**從商品那一邊帶著商品去進貨開單頁**:商品詳情「編輯」旁邊的「進貨」;新增商品存好會自動選到那一筆、訊息條上有「進貨」;「新增手機型號」建完的按鈕(再建機型 / 商品列表 / 前往進貨,有建中古的品項再多一顆「中古收購」;字數一致)。網址是 `/purchases/new?add=商品編號,…`(一次最多 60 個;帶不完的寫 `&more=幾項`)。**規則只有 `frontend/src/lib/purchasePrefill.ts` 一份**(有測試):`purchaseLinkFor`(一般商品 → 進貨開單頁;只有中古機 → 中古收購,那一頁不預先帶商品;虛擬 / 停用 / 還沒有編號 → 沒有「進貨」這顆)、`readPrefill`(讀網址:只收正整數、不重複、照順序)、`withPrefill`(把還沒做完的寫回網址)、`carriedQty` / `draftQty`(帶過來的數量)、`sortFetched`(查回來的哪些能加)、`prefillReport`(沒加進去的要怎麼講)。**進貨開單頁只在打開時讀一次**(`PurchaseWorkbenchPage` 的 `carryIn`;內嵌的中古廠商收購不讀):逐一 `GET /products/{id}/`,放進進行中的草稿(不會洗掉原本的明細)。跟刷條碼(`addProduct`)不一樣的兩點:(1) **草稿裡已經有的商品什麼都不改**(「帶過來」不是「再刷一件」,來回按兩次「進貨」不會多一件);(2) **配件(不追序號)新的一行數量是 0** —— 帶過來不代表進了幾件,要刷(0 → 1)或打數量才算,**0 存不了**(數量框是紅的,儲存會講「數量要大於 0」;草稿載回來還是 0,不會變成 1)。先放 1 的話,接著把每一件都刷一次就多進一件。序號商品照舊是一個空位(刷到序號才算一台,空位沒刷存不了)。查回來的商品以伺服器現在回的為準再分一次(`sortFetched`:中古機、虛擬商品、停用的、查不到的都不加)。**沒加進去的一律留在明細上方、自己的那一條(`carryNotice`)**:只有人按「知道了」才消失(勾選商品 / 批次貼上的結果不會把它換掉、換一張新單也留著),**沒按之前不能儲存**—— 中古機、虛擬商品、停用的、查不到的(講幾個;一個最多等 15 秒)、這張單已經送出、一次帶不完的;同一種只寫一行(最多三個品名 + 總共幾項),內容多了自己捲、「知道了」固定在右上(不會被擠到畫面外);一個帳號一份(存在 sessionStorage,不跟著草稿)。**這一段是晚一點才回來的,跟人手上的事要排好順序**:(a) 還在處理的掃碼先做完才動明細(`scanApi.idle()`);**人正在刷別的那一行就不換「正在刷序號的那一行」**(原本有在刷的那一行,而且從收到這一批到現在人動過任何東西 —— 點了哪裡、按了鍵、打了字,包含點別行的「已刷」、直接在序號格子裡打字 —— 或正在刷的那一行已經換過、掃碼框裡有沒送出的字、游標在序號格子裡:都不換;帶過來的照樣加進明細,要刷它再點那一行。原本沒有在刷的、或人什麼都沒碰,才換成帶過來的那一個);(b) **這張單正在儲存、或已經送出還不知道結果:不加,當下就講、留著**(不等查回來);儲存按下去之前就在查的,**儲存會等到佇列不再變才定稿**(`prefillRef`),等的時候人離開了就不送、等到的結果有沒加進去的就先停(儲存看的是當下就寫的 `carryNoticeRef`,不是還沒重畫的 state);(c) **一批一批排隊做**(`carryQueue`;這一頁開著的時候,訊息條上的「進貨」會送來新的一批),而且**網址永遠寫著「所有還沒做完的」**(`withPrefill`:新的一批進來就把前面還沒做完的併回網址,做完一批拿掉一批;自己改寫網址的那一筆帶記號 `CARRY_SYNC`,不會被當成新的一批)—— 還在查的時候重新整理、離開再回來,一個都不會少(再帶一次也不會多:已經有的不動);(d) 一批做完,**先把加進去的明細存進草稿(`saveDraft`,不等那 250 毫秒)、沒加進去的寫進提醒,才把它從網址拿掉**(別的參數留著)。帶過來的第一個排在最上面、也是正在刷序號的那一行。商品管理新增存好會清掉搜尋(回到「近期新增」),新的那一筆才一定看得到。後端沒有動

### 進貨時找不到當場建

2026-10-07 起(新手商品建檔 R1 第二小包)。人在進貨開單頁刷到 / 打到系統裡沒有的商品,**不用離開這張單**:當場先找一次、確定沒有就建,建好(或找到既有的)直接回到這張單的明細上。只有一般進貨有(內嵌的中古廠商收購、銷貨、調撥都沒有)。**入口在掃碼框**(`components/workbench/ScanBox`,頁面有傳 `onCreate` 才出現):(1) 下拉最下面固定一列「建立商品」(有候選時寫「都不是,建立商品」;滑鼠點,或上下鍵移到那一列按 Enter —— 條碼槍沒動過上下鍵,不會誤觸);(2) 「沒加入」那一排,**因為找不到是哪個商品**才沒加進去的那幾筆旁邊多一顆「建立」(`Missed.creatable`:搜尋 0 筆、相似的太多、不是完全相同,以及頁面的 `onScan` 回 `{ problem, unresolved:
