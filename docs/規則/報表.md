## 規則

### 報表只有一套定義(自由組合)

`apps/analytics/`:`catalog.py` 是**指標與角度的唯一定義**(事實表:銷貨 / 銷退 / 進貨 / 收款 / 退款 / 庫存快照 / 舊 POS;指標 = 直接加總的 `Base` + 由別的指標算出來的 `Derived`)。**角度裡有單上的兩個人(2026-10-12):「客戶」`customer`(來源)、「會員」`member`;只有管理員能用**(`Dim.roles`,`catalog.may_use()`:分組、條件、下拉的名單、選單裡都收 —— 照這兩個分就是客戶排行;店員送來回 400「沒有權限照『客戶』看」,管理員存成共用的這種報表在店員那邊打不開)—— 銷貨、銷退(看銷退單自己記的,建立時照抄原單)、收款、退款、門號合約可以用(`catalog._people_paths`),進貨 / 庫存 / 舊 POS 不行;沒有會員的歸「(非會員)」,同名的兩位是兩列(照編號分),報表與下拉只給姓名、不帶電話。報表畫面與之後的自然語言都只能送**查詢單**(`engine.py`:指標 × 分組最多 3 個 × 期間 × 條件 × 比較),後端照定義驗證,指標不能用那個角度切就回白話錯誤、不默默給 0;沒有任何入口接受資料庫指令或欄位名稱。**新的報表需求 = 加指標或加角度,不是寫新的報表頁、新的查詢**。「銷售」類指標只算計入毛利的明細(收購二手另外一欄),所以 銷售額 − 成本 = 毛利 是同一批明細。庫存是「期間內最後一次快照」,不跨日加總;「最後一次是哪一天」看 `StockSnapshotDay`(那天有沒有拍過),**不是看明細**:賣到 0 的東西沒有明細,看明細會退回去報最後一次有貨的數量。舊 POS 的門市 / 商品 / 業務員走對照表,沒對到的歸「未對照」;舊系統的「未稅額」欄位語意不一致,不採用。合計另外算(不受筆數上限影響,單數不重複算)。存起來的報表(`SavedReport`)條件存**代碼**不存編號(還原備份後編號會換),打開時換回現在的編號,找不到的講出來。付款方式可選的代碼 = 現在的主檔 + 單據上用過的(主檔已刪的顯示「代碼(已刪除)」):刪掉用過的付款方式,歷史的錢照樣篩得到。**誰看得到什麼(2026-10-10 起,員工帳號權限第三批)**:要有「自訂分析」那一項才用得到這一組 API;**鎖在門市的帳號只算自己門市** —— 引擎強制(`engine.run(..., only_warehouse=locked_warehouse_id(user))`:不管查詢單的條件怎麼寫,門市條件一律換成自己那一家;分不出門市的指標直接拒絕,所以**新增的事實表一定要有 `warehouse` 這個角度**,有測試擋),結果的 `applied.filters` 看得到是哪一家;鎖了卻沒設門市 → 403;沒鎖的帳號與管理員照舊看全公司(2026-10-04 的「報表暫時不依門市上鎖」到此為止)。毛利(實際成本)不藏;只給管理員的指標填 `Base.roles` / `Derived.roles`(公司佣金那幾個),只給管理員的角度填 `Dim.roles`(客戶、會員)。**固定的報表(`analytics/presets.py`)**:業績彙總(照業務員)、商品排行(照商品 / 品類 / 品牌,最多 200 筆)、每日彙總(一天一列,一次最多一年)、**客戶排行(2026-10-12;2026-10-23 改名「來源排行」、`by` 的字改成來源 / 會員;只有管理員看得到;取舊歐睿 SA040 毛利彙總表照客戶 / 會員:`by` = 客戶(這張單的來源)/ 會員(實際的那個人或公司),銷貨單數、淨銷售額、業務員毛利、實際毛利(管理員),照淨銷售額排、畫面最多 200 筆)**、**開通統計(2026-10-12;取舊歐睿 SIM031 開通數量統計:`by` = 電信 / 方案 / 業務 / 門市;欄 = 新辦、續約、攜碼(成交的數,沒有扣)、退掉、淨開通、業務員佣金、公司佣金(管理員)。一門 = 銷貨單上有方案的那一行;作廢的單不算;退掉的扣在退的那一天 —— 跟佣金明細(逐筆)、業績彙總的門號佣金是同一批明細,三邊的數字要一樣。門號的三個角度 `carrier` 電信業者 / `plan_kind` 方案種類 / `plan` 方案,銷貨、銷退也能用了(銷退走 `original_item`;沒有方案的行歸「(不是門號)」);三種方案的名單 `catalog.PLAN_KINDS` 是另外列的一份,測試會跟 `TelecomPlan.Kind` 比對)**、**開通統計可以照上線日看(2026-10-12,owner「照上線日」;`?date=start`,預設 `doc` 開單日):`presets.Report.dates` 的 `Basis`(另一種日期 = 另一組欄;回應的 `dates` / `date` 給畫面出「日期」下拉,只有一種的報表是空的)。上線日 = `SalesOrderItem.activation_date`(新辦 = 開單日;續約 / 攜碼人填、可以事後改)。事實表 `started`(銷貨明細裡有方案的那幾行,期間看上線日)與指標 `started_new|renewal|portin`、`started_net`、`started_net_staff_commission`、`started_net_company_commission`(管理員)。**退掉的仍然扣在退的那一天**(電信商追回佣金出在後來那一期,不回頭改上線那個月),而且**只扣有上線日的那幾門**(`return_started*`;沒填上線日的當初沒算進任何一期,退掉時也不能扣)。沒填上線日的不在任何一段期間裡,回應的 `pending` 另外寫一句「未填上線日 N 門」(不管哪一天開的單;作廢、已經整張退掉的不算;鎖門市的只算自己那一家),字由伺服器給。照開單日的數字不變(跟佣金明細、業績彙總三邊一樣);**佣金明細、業績彙總照舊只看開單日**,所以選上線日時跟那兩頁對不起來是正常的。匯出的檔名在不是預設的日期時加字(「開通統計-上線日」,`lib/fixedReports.ts::exportTitle`)**—— 內容由伺服器定(哪幾欄、欄名、排序、哪幾欄只給管理員;期間旁邊那幾個字也是:`Report.note`,預設「已扣銷退」,畫面不自己寫死),**數字全部走引擎**,畫面只選日期與門市;`GET analytics/presets/<staff|products|daily>/?from=&to=&warehouse=&by=`,各看各的勾。**一律扣銷退(退的那一天扣回去)**,所以跟銷貨日報的合計對不起來是正常的(銷貨日報不列銷退);整列都是 0 的不列(個人收購沒有業務員、不計毛利,不然會多一列「(未指定)」)。為了它們多的指標:「沖回業務員佣金」「沖回公司佣金(管理員)」「門號業務員 / 公司佣金(扣銷退)」「業務員毛利加佣金(扣銷退)」(`staff_total` = 銷貨單清單上每張單的「業務員毛利」(那裡含門號佣金)加起來再扣銷退);原本的「門號業務員佣金」「門號公司佣金」仍然是沒扣的。**佣金明細另外一支**(`sales/commission_views.py`,`GET telecom-commissions/?from=&to=&warehouse=`):期間內每一行有方案的銷貨明細一列,期間內的銷退另外一列負的(列在退的那一天);**合計 = 同一段期間業績彙總的「門號佣金」**;公司佣金只有管理員的回應裡有;一次最多一年、最多列 2000 筆(合計是全部的)。畫面:`pages/reports/FixedReportPage`(三張共用)、`CommissionLinesPage`、`ReportRangeBar`,規則在 `frontend/src/lib/fixedReports.ts`(今天與月初用這台電腦的日期,不用 `toISOString`)。每日彙總沒有「實收」:現金的數字只有營業日報那一份。API:`analytics/catalog/`、`query/`、`options/`、`reports/`、`presets/<key>/`

### 報表的匯出(全站一份寫法)

2026-10-12 起(取舊歐睿報表優點的第 3 批:舊系統每一張都能轉 Excel)。**寫檔只有 `frontend/src/lib/csv.ts` 一份**(`csvCell` / `toCsv`)+ `components/downloadCsv.ts`:有逗號 / 引號 / 換行的包起來;**12 位以上的純數字(IMEI、條碼)與開頭是 0 的純數字(電話、門號)寫成 `="…"`** —— 不然試算表會把 IMEI 變成 3.56E+14、把 0912… 開頭的 0 吃掉。金額用 `intStr`(整數、不加千分位)。**頁面裡不要自己組 CSV**(`reportExports.test.mjs` 會掃 `pages/` 與 `components/`;例外只有三個「下載匯入範本」:給人填了再匯回來的,不能把數字包成文字)。各張的內容在 `lib/reportExports.ts`(有測試):`fixedReportTable`(業績彙總 / 商品排行 / 每日彙總;欄位照伺服器給的,只給管理員的欄店員的資料裡本來就沒有)、`commissionTable`、`stockMatrixTable`、`contractTable`;最後一列是合計(畫面有合計的)。**原則:檔的內容 = 那個帳號在畫面上本來就看得到的**(不新增端點、不新增權限)。要翻頁的清單用 `collectPages` 把每一頁抓完(庫存查詢:一頁 1000 個、最多 30 頁;合約到期:照同一個游標、最多 100 頁);**超過上限不給檔**:每一頁的匯出都走 `exportIfComplete(有沒有被截短, 檔名, 排表, 存檔)`(頁面不直接呼叫 `downloadCsv(`;超過就只回一句「請把條件縮小再匯出一次」—— 老闆把只有前幾列的檔交給會計,加總會少一截)。商品排行畫面只列前 200 名,**匯出時另外跟伺服器要全部的列**(`analytics/presets/<key>/?export=1`,`presets.run(everything=True)`;權限與門市範圍跟畫面那一支是同一個函式;引擎自己的上限 2,000 列還在),不能拿畫面上那一份。匯出用的條件一律是**畫面上查出來的那一份**(已套用的),名單還沒更新時(合約到期剛打完字)不能按。**檔名** `exportFileName`:報表名稱_門市_期間(沒選門市 = 全部門市;鎖在門市的帳號 = 自己那一家)。**合約到期的整份客人名單只有管理員有「匯出」那一顆**(`isManager`;店員照舊在畫面上一筆一筆看 —— 這只是畫面不給按鈕,不是伺服器擋;要不要開放、要不要記誰匯出,等 owner 決定)。進貨單清單沒有匯出(它只列最近的單;整段期間的用進貨明細)

### 清單怎麼拿(全站)

2026-10-13 起(L1 清單不再默默少列)。**伺服器**:預設分頁是 `apps/core/pagination.py::Paging` —— 一頁預設 50 筆、`?page_size=` 最多 500、**要求比 50 少的照舊給 50**(刷條碼與搜尋下拉 `api/search.ts` 一直帶 10 / 20、實際拿 50,有幾處靠「拿回來的只有一台符合」做判斷,不讓它變少);排序最後補編號(`stable()`),一頁一頁拿的時候同分的列不會重複 / 漏掉。合約到期、舊系統、報表各有自己的分頁,不走這一支。**畫面**:讀清單一律走 `api/hooks.ts` 的四支(規則在 `lib/listAll.ts`),**每一處都要明講是哪一種** —— `listAll`(整份都要:下拉的選項、管理頁、有合計的清單;一頁 500 筆拿到沒有下一頁,**超過 5,000 筆報錯、不給一部分**)、`firstPage`(本來就只列最近的 / 找到的前幾筆)、`topPage`(第一頁 + 總共幾筆,畫面要寫「只列前 N 筆」的)、`listSome`(單據清單:有選日期 / 狀態才整份)。**不可以再寫「拿第一頁當全部」**(以前共用的 `list()` 就是這樣:第 51 筆看不到也搜不到、合計只加了 50 筆);`lib/listAll.test.mjs` 會掃 `api/hooks.ts`,新的清單要只拿第一頁得改那一份名單。會一直長的清單不整份拿:**會員名單**問伺服器(`useMemberList(search)`:照姓名前 100 位 + 總數,打字由伺服器查電話 / 姓名 / 身分證 / 統編 / 聯絡人 / 會員號;選到的那一位用 `byId` 對編號,對不上不顯示表單);**雜支 / 現金調整 / 代收話費**帶期間(預設本月,清單與合計 = 這段期間沒作廢的)。**會員 / 客戶頁的「N 筆 · 累計 · 最近」由伺服器算全部**:`GET sales-orders/summary/`(跟清單同一套條件與門市範圍,只算沒作廢的);底下的單只列最近 100 張並寫明。

### 銷貨日報的資料、進貨明細(兩張明細)

### 商品業務員成本
