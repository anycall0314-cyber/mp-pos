## 規則

### 批發(經銷商之間互相買賣)

2026-10-14 起(T1 賣家 + T2 買家(平台內)+ T3 對外的接法;owner:「上面除了中古機，要照我的，其他的照你建議一路開工做完」;規格 `docs/api/買賣串接規格_v2_草稿.md`,門市照著做的步驟 `docs/批發_使用步驟.md`)。**錢不經過平台、只管帳。** **賣家那一半 = `backend/apps/trade/`**(每一張表都是賣家那家公司的,進公司備份;單號 `TO-` 進單號下限):`TradeSetting` 批發設定(開放批發、中古機批發價三種算法、進貨上架、平台販售、下單接單、顯示數量)、`TradePartner` 往來的同行(記對方公司的識別碼 `backup_uuid`,**兩家公司不用外鍵互指**;未核准 / 往來中 / 不往來;折數、付款方式)、`TradeInvite` 一次性往來代碼(只存雜湊、七天;**不提供經銷商名單給人挑**)、`TradeUnit` 中古機一台一筆上架、`TradeProduct` 按數量賣的商品開不開放與固定批發價、`TradeOrder` / `Line`、`TradeShipment`(一次出貨 = 一張銷貨單)、`TradePayment`。**「在不在賣」是算的**(`listing.units_for_sale`:有上架 + 那一台在庫 + 沒被訂著):賣掉、調撥途中、送修自己消失;賣掉另外關掉上架(銷退回來不會自己回到清單)。中古機進貨 / 收購就照設定上架(`listing.after_intake`,掛在 `purchasing.commit_purchase_order` 與 `sales.acquire_secondhand_from_member`;表單可以個別指定 `wholesale_list` / `wholesale_price`;算不出正的批發價就不上架、不擋進貨)。**批發品(按數量賣的)批次上架 / 改價**(owner 2026-10-14:「一般商品也要可以用批次上架，可以依品牌，類別，關鍵字，型號等，用多重分類去選取與批次上架改價，未來會有批發手機維修零件的進駐」):`GET trade/products/` 類別 / 品牌 / 型號(商品本身的機型或 `ProductRelation` 適用的機型)可以各選好幾個、關鍵字、狀態、批發價種類、新到幾天(有沒作廢的進貨),每一類帶數量、一次最多 2,000 個。批發價三種:固定價 / **門市價的幾 %**(`TradeProduct.percent`,每個同行一樣、門市價改了跟著變;紅隊:存成算好的金額會讓人以為跟著門市價)/ 照同行折數(`listing.price_for`)。`set_products` 整批一起成立、只改價不會順便開放、每個有變的記改價紀錄。畫面勾著的一起開放 / 收回 / 改價,每一列「改成」先顯示改完的價,改價與十個以上要再按一次(那一行只有數字,把 70 打進固定價會標「價差大」)。**報價連結**(owner 2026-10-14:「報價連結這個想法超棒可以，但是要可以關閉連結分享」):給沒用這套 POS 的同行用手機看現在的價(`TradeQuoteLink`、`trade/quote.py`、`quote_views.page`,網址 `/api/trade/quote/<一串>/`,不用登入)。**一個同行一條**(紅隊:共用的一條會被轉給零售客與對手)—— 同行帳那一列「報價頁」開 / 關 / 換新、看過幾次;加外部同行就先開一條。內容跟他在平台內看到的一樣(他的折數、他看得到的;中古機一台一行(成色 / 電池 / 備註 / 編號)、型號預設收起來(那一列寫每個成色幾台從多少起)、上面篩成色 / 電池 / 價格、全新機與配件在「其他商品」(成色電池篩不到)、每一行「加入」底下一次複製(帶編號與報價時間))。每條每分鐘 30 次、不快取、不給搜尋引擎收錄、不載外面的東西;不往來 / 關掉批發 / 維護中都打不開。不進公司備份,還原之後全部要重開。**中古機的價靠價目表**(owner 2026-10-14:同型號在庫上百台、行情天天變;「型號成色電池都可能會決定價格」「批次全選,再取消部分勾選獨立定價」「改價紀錄也要」):一格 = 型號 + 成色 + 電池區間 + 有沒有備註 → 一個價(`TradePriceRule`;規則在 `trade/pricing.py`,前端 `lib/trade.ts` 同一套)。**全公司符合那一格、沒有獨立定價的在庫機器都用那個價**(不只畫面上那幾台;下架中的也改,再上架時價是對的),新進貨的自動用;只有被明講的才是獨立定價(`TradeUnit.own_price`:自己那一列打價、或取消勾選)。兩格都符合 → 比較細的算數(成色 → 電池 → 備註),一樣細的電池區間不能重疊。價還是存在 `TradeUnit.price`(改一格時 `pricing.reprice` 把用它的一起改),下單、對外都讀那一個。每次價錢變了記 `TradePriceChange` / `TradePriceChangeUnit`(誰、哪一格、每一台從多少變多少)。畫面:型號清單每一列上就有那個型號的價目,當場改、一次存(`trade/units/rules/`);點進型號 = 那個型號的每一台,勾 = 跟價目、沒勾 = 獨立,上面點的成色 / 電池 / 備註就是「價目」那一格;改到價目、改成獨立、或一次十台以上要再按一次。`listing.put_on` 整批一起成立、鎖的順序商品(改價目時)→ 序號、一次最多 2,000 台;價目是全公司的,鎖門市的店員不能改(只能替自己門市的定獨立價)。畫面送出時帶著它看的型號 / 門市,伺服器逐台核對(換門市那一下手上是上一份清單的話會整批不動)。**一台中古機同時只會被一張單訂著**(`TradeOrderLine.holding`,資料庫有唯一限制;下單先鎖那一台才看還在不在賣)。**被同行訂走、還沒出貨的那一台門市要賣(紅隊第 1 條)**:`sales.commit_sales_order` 鎖到序號之後問 `trade/holds.before_sale` —— 沒明講就整張擋(錯誤帶 `code: trade_hold` 與是哪幾台),畫面(銷貨工作台)問「賣給客人 / 留給同行」,選賣給客人 → 再送一次帶 `release_trade_units`,同行那一行當下取消;**擋在過帳那一層**。**出貨(紅隊第 2 條)**:`/trade` 待出貨直接刷機(`shipping.scan` 找出是哪一張單的哪一行;中古機那一行也可以用手勾)、「不出」一行、其餘照出;出貨 = 開一張銷貨單(客戶 = 那個同行,自動建「同業」;付款方式「同行記帳」`peer`:非現金、**建的時候就是停用的**,櫃台結帳不會選到)+ 運費一行(虛擬商品「批發運費」);同一把鑰匙不出兩次;**批發出貨開的銷貨單不能從銷貨單那邊作廢**(`holds.guard_void`),要從批發單「取消出貨」(`shipping.void`,另外要「作廢銷貨單」的權限)。**收款(紅隊第 3 條)**:對一個同行記一筆收到的金額(`payments.record`),**哪一筆銷哪一張單不存、每次看的時候由舊到新算**(`payments.ledger`;出貨取消、整張銷退、收款作廢之後欠多少自己會對);只算出過貨的。**鎖的順序:商品 → 序號 → 批發單(動明細之前一律先鎖單)→ 庫存餘額**(`trade/base.py`;出貨先鎖要出的序號才鎖單;銷貨過帳把鎖拆成「序號 → 問批發 → 庫存餘額」;有四條兩條連線的測試)。**對買家講話只有一支 `trade/api.py::handle(賣家, 買家, 方法, 路徑, 內容)`**(看得到什麼只有這裡一份:只回開放給他的商品與他的價錢、他自己的單;成本一律不出現、出貨之前不露序號;中古機 = 商品帶 `per_unit`、每一台是 `specs[]` 的一項;沒開放 / 不往來 → 看商品與下單回 403,**自己已經有的單照樣查得到**)。**買家那一半沿用 `vendor_orders`**:開了批發的經銷商 = 廠商名單上自動多一筆(`Vendor.protocol = platform`、代碼 `d-` + 賣家識別碼前 12 碼、`seller`;賣家存批發設定時 `platform.sync_vendor`;**平台管理員的廠商名單不列它**);`platform.Client` 把「打廠商」改成直接呼叫 `api.handle`(原本放金鑰的位置放的是程式組出來的標記 `platform:公司:門市`,不是使用者輸入的);誰看得到問賣家那邊(`partners.can_see`:核准的,或賣家開了平台販售 → 只看得到中古機),自己看不到自己。沒有金鑰 → 看管理員「開通」(跟半自動同一格);**管理員在叫貨串接輸入往來代碼(`POST vendor-orders/join/`)→ 變成核准的同行、每一間門市自動開通**。叫貨頁:中古機一列一台、用勾的(只能訂 1)、缺貨不能訂;付款方式是賣家定的(買家的紀錄跟著寫);`POST vendor-orders/{id}/cancel/` 對同行的單 = 跟對方說還沒出的不要了。**到貨入庫支援帶序號的商品**(`receiving.py`):對方出貨單上的每一台(碼、成色、電池、備註)直接變成這邊庫存裡的那幾台、成本 = 單價 + 攤到的運費,**同一台不會入兩次**(`VendorReceiptItem.serials`;進貨單作廢的那幾次不算);帶序號的只能入到帶序號的商品,一台一筆的對逐台記機況的、全新的對全新的(`_fits`);中古機的品名對照記在商品那一層(連一次、每一台都算)。**買家收進去的貨,賣家不能再變回自己的庫存(複審第一輪 P0)**:買家每次到貨入庫、每次作廢到貨入庫開的進貨單,都在**同一個交易裡**跟賣家回報這張單到現在為止收了多少、哪幾台(`vendor_orders/services.report_received` → `POST /orders/{no}/received` → `trade/shipping.report_received`,記在 `TradeOrderLine.received_qty` 與 `TradeShipmentSerial.received`;收的不能比算數的已出多);賣家「取消出貨」與整張銷退(`sales.commit_sales_return` 一開始問 `trade/shipping.before_return`)看的是「少了這一次,其餘算數的出貨還蓋不蓋得住買家已經收的」(`received_block`)—— 要退貨:買家先作廢那張進貨單,賣家才取消出貨 / 銷退。買家看到的每一行「已出」只算現在算數的出貨(取消的、整張銷退掉的不算),而且**對方有給每一次出貨的(`Line.strict`),還沒出的不能先入**(膜總裁照舊只提醒)。**賣家的資料還原中(公司維護鎖)**:買家這一側進來的請求不經過賣家的登入驗證,`platform.Client` 自己擋、回 503(= 連不到;下單算「不確定」、之後同一把鑰匙再送),加入同行也擋(複審第一輪 P1)。**複審第二輪(最後一輪;這兩處修完沒有再送審)**:(1) 買家回報的是整張單現在的樣子,所以**要鎖著買家自己那張叫貨單才算**(到貨入庫整段鎖著;作廢進貨單在一開始 `receiving.before_purchase_void` 鎖)—— 不鎖的話「作廢 A 的進貨單」與「入庫 B」同時來,作廢那邊先算好、後送出,會把 B 蓋掉;買家這邊的順序:叫貨單 → 進貨單與庫存 → 賣家的批發單。(2) 銷退單的端點原本就先鎖原銷貨單,批發的檢查(那一次的序號 → 批發單)要排在它前面(`sales/views.py`),不然跟同一次出貨的「取消出貨」互相等。**對外的接法(T3,2026-10-14)**:不在這套 POS 上的系統用金鑰來買 —— `GET/POST /api/trade/v2/…`(`trade/public_views.py`;全平台同一個網址,`Authorization: Bearer <金鑰>`,**不用 POS 的登入**,最後一樣是 `api.handle`)。金鑰(`trade/keys.py`、`TradeKey`):賣家的管理員在同行帳「加外部同行」(名稱 + 怎麼聯絡,兩格都要)→ 發一把 `mpk_` 開頭的金鑰,**原文只在發的那一次回給畫面、資料庫只有雜湊**;「換金鑰」舊的立刻失效;一把金鑰 = 一家賣家的一個同行;每分鐘最多 120 次(一句更新算,超過 429);賣家的資料還原中回 503;**不進公司備份、還原時清掉**(舊金鑰不能自己活過來,要重發)。外部同行預設付款「匯款」。**動手前紅隊三條**:(1) 這套 POS 當買家時網址與金鑰貼錯地方 → 新格式的廠商存金鑰時問對方「會哪些」並把對方自稱的名稱顯示在串接卡片上(`Vendor.remote_name`);(2) 外面今天才接上的跟月結的老同行在同一張清單 → 單上標「對外」與聯絡方式,不是月結的在出貨那一排提醒「預收 N / 未收款 還差 N」(`lib/trade.prepayNote`;**只提醒不擋**,錢不經過系統);(3) 單上看不出怎麼取貨 → 下單就要講(`orders._header`:沒講 = 自取;宅配要有收件人、電話、地址)。**這套 POS 當買家、跟外面照新格式的賣家買**:平台管理員在廠商上把「對方的格式」設成新格式(`Vendor.v2`;**舊格式的廠商(膜總裁)完全不多問**)→ 門市存金鑰時問一次 `GET /capabilities`(`services.learn`)→ 對方說會的才有:取消叫貨(`cancel`)、對帳單(`statements`;紀錄頁「看對帳單」,平台內的同行也有)、回報收貨(`receipts`;外面的賣家不在同一個資料庫,只能提交之後盡力報一次)。**通知(賣家主動打買家的網址)沒做**:要系統對外發請求(防打到內網、重試、排程),現在沒有人要接;查單永遠是對的。複審第一輪(T3):這套 POS 跟外面新格式的賣家買,金額、運費、付款方式也一律跟著對方現在回的(`services.follows_seller`;原本只有平台內的同行);對外端點的查詢字串照一般網址解碼、看不懂的 `since` / 日期回 400;回報收貨先看型別;沒料到的錯也回講好的樣子(500 `error`,並記錄)。`trade/test_backup.py` 實測備份 → 還原:批發的表都回來、金鑰清掉、單號不重發。測試 `trade/test_public.py`(含「這套 POS 透過自己的對外端點跟自己買」)。資料庫變更 `trade.0002`、`vendor_orders.0010`。權限:員工帳號「批發出貨」(`trade_sell`:看單、接單、出貨、中古機上架);批發設定、同行與代碼、批發品與固定價、收款只有管理員。畫面:`/trade`(銷貨作業 → 批發單;分頁 待出貨 / 全部單 / 中古機 / 批發品 / 同行帳 + 設定;`pages/trade/`、`api/trade.ts`、`lib/trade.ts`)、收購表單多「批發上架 / 批發價」、叫貨串接多「加入同行」。**還沒做**:通知(賣家主動通知買家)、維修串接(T4,等智盛)、標準機型直接對品號(等 M1)。**已知的限制**:一邊還原到較早的備份,另一邊已經叫 / 收的單不會跟著回去(跟外面的廠商一樣)。測試 `trade/tests.py`、`vendor_orders/test_platform.py`、`lib/trade.test.mjs`。資料庫變更 `trade.0001`、`vendor_orders.0009`
