## 規則

### 廠商叫貨(多廠商;第一家是膜總裁 B2B)

**多廠商 + 平台定的廠商類別(2026-10-10 owner:「廠商叫貨區，未來會陸續去招商家入，所以要設計多廠商以外，還要多類別可制定」;第一步 地基)**:有哪些類別、哪些廠商是**平台的名單**(`VendorCategory` / `Vendor`,不屬於任何公司、**不進公司備份**;只有平台管理員能改:`/platform/vendor-categories/`、`/platform/vendors/`,畫面在「平台管理 → 廠商」;**只能停用、不能刪**)。廠商一筆 = 代碼(建了不能改)、名稱、掛在哪些類別、怎麼接(現在只有「全自動(標準格式)」= 膜總裁那一套)、**對方的網址(一定要 https;各家門市的金鑰只會送到它所屬那一家的網址)**、金鑰的開頭(有填才檢查)。公司的資料(`VendorLink` / `VendorOrder`)**只記廠商代碼 `provider`,不用外鍵**指到平台的名單(備份檔會搬到別台);名單上找不到那個代碼 → 單照樣看得到(名稱顯示代碼),不能再對廠商做事。每一支店家的 API 都要帶 `vendor`(代碼);**名單上只有一家在合作時可以不帶**。**類別只用來篩廠商**(紅隊):同一家廠商掛幾個類別都是同一個入口、同一份購物車(草稿一個帳號 × 門市 × 廠商一份,`lib/vendorPick.ts` 的 `draftSlot`);停用類別只是不顯示,要停叫貨是停廠商。**停用的廠商**:不能看商品、叫新的貨、新開通或換金鑰;已經叫的單照樣可以重送、更新進度、到貨入庫、改入庫設定、拿掉金鑰。**誰能叫貨**(紅隊:只有一個勾的話,開通高單價的廠商之後不是店員也能跟它下大單、就是連保護貼都不能叫):員工帳號的「廠商叫貨」照舊是總開關,另外 `VendorLink.clerk_ordering`(每家門市 × 每家廠商;預設 True)= 這家店的店員能不能跟這家叫 —— 關掉時店員看商品 / 叫貨 / 再送一次都 403,紀錄、更新進度、到貨入庫照舊。跟廠商講話的那一支從名單來:`vendors.client(vendor)` → `standard.Client(網址, 名稱)`(`standard.py` = 原本的 `moceo.py`;之後格式不一樣的廠商在 `vendors.client` 分);訊息裡一律寫那家廠商的名稱,不寫死任何一家。**owner 同一天補充:招商最大的問題是各家系統接不起來(多半是租的、沒有串接功能),初期走半自動** → **半自動的廠商(2b,2026-10-11;`manual.py`)**:廠商那邊什麼都不用改。「怎麼接」多一種 `manual`(不用網址;多 聯絡方式 / 接單信箱);**價目表 `VendorItem` 是平台的資料**(不進公司備份;只有平台管理員能改;料號沒填系統給 `N0001`…、建了不能改、只能停用;`/platform/vendors/{id}/items/`、`/platform/vendor-items/{id}/`、整批貼上 `…/items/import/`:沒給 `apply` 只預覽、有一列有錯整批不存、有料號照料號對不然照「品名 + 規格」、**已有的品項空著的格子 = 不改**;畫面拆 Excel 的字在 `lib/vendorManual.ts` 的 `parseSheet`)。**開通沒有金鑰**:管理員在叫貨串接選開通(`VendorLink.opened`);串接回 `ready`(全自動 = 有金鑰、半自動 = 開通了),畫面一律看 `ready`;半自動的不用填發票那幾格。**叫貨單 POS 自己成立**(`VendorOrder.manual=True`、單號 `VO-` + 流水、直接已成立),**整段不打任何外部系統**(測試釘住);清單 = 價目表上啟用的、價錢是參考價、**沒有參考價也可以叫**;回應帶 `message`(要傳給廠商的那一段,**不寫價錢**)。**傳了沒 / 進度 / 取消是人記的**:`POST /vendor-orders/{id}/sent/ {sent}`、`/cancel/ {cancelled}`(要「廠商叫貨」;取消只是標記、可以恢復、取消的單照樣入得了庫)、`/progress/ {note}`(兩項有一項);沒有 更新進度(不問任何系統)/ 再送一次 / 認外面的單。**到貨入庫照店家叫的單**(`manual.plan` / `manual.receive`,同一支 `/receive/`,多收每一行的 `unit_price` 與 `freight`):數量不預先帶(「全部到齊」)、**實際單價與這一次的運費入庫的人填**(0 元 = 沒收錢,數量照入不計價;運費算不算進成本照門市設定)、**可以入這張單沒叫的品項**(價目表上現在有的,或這張單入過的)、**比叫的多只提醒不擋**;進貨單一樣未稅、貨到付款記現金、同一把鑰匙不入兩次、對照與舊畫面的保護同一套。畫面:`ManualReceiveDrawer.tsx`、紀錄展開的那一塊(複製內容 / 標記已傳 / 取消叫貨 / 儲存進度)、叫貨串接的「開通」、平台管理的「價目」,規則在 `lib/vendorManual.ts`(有測試)。自動寄 Email:owner 2026-10-11 說先不做(複製貼 LINE 就好);`order_email` 先存著、沒有東西讀它。以下是膜總裁那兩步(叫貨、到貨變進貨單)的規則,多廠商之後一樣適用。 2026-10-10 起(owner:「我現在想做串接 moceo b2b 的串接」;他選:叫貨 + 到貨變進貨單、每家門市各一把金鑰、店員可以叫貨可關掉)。**兩步都做了:第一步叫貨、第二步到貨變進貨單。** `apps/vendor_orders/`;對方的 API 在 `~/moceo-b2b/docs/api-v1.md`(另一個專案,要改它先問 owner、傳訊息給那個工作階段)。**金鑰**:一家門市 × 一家廠商一筆 `VendorLink`(預設的付款 / 取貨 / 收件 / 發票;**不含金鑰**)+ `VendorSecret`(金鑰,用 `SECRET_KEY` 導出的鑰匙加密;任何回應都沒有原文,前 12 碼只有管理員看得到;**不進公司備份、還原前清掉** —— 還原之後要重新貼);只有管理員能設(`POST /vendor-links/`,存之前拿它去問廠商一次,廠商不認得就不存)。金鑰一律 `mk_live_` 開頭,**是不是沙盒看廠商每個回應裡的 `sandbox`**(存在 `VendorSecret.sandbox`,每次跟廠商要清單時跟著更新;畫面標「測試金鑰」「測試單」)。**`VENDOR_SANDBOX_ONLY=true`(測試環境設)= 只收廠商明講是沙盒的金鑰**,存金鑰、看清單、叫貨都擋 —— 不然有人把正式金鑰貼到測試站,測試時下的就是真的單。**叫貨**(要員工帳號的「廠商叫貨」`vendor_order`;鎖在門市的帳號只能用自己門市的金鑰、只看得到自己門市的叫貨單):`GET /vendor-orders/catalog/?warehouse=` 每次現抓廠商的商品與這個帳號的進價(有規格的商品一個規格一列;沒有報價的不能叫);`POST /vendor-orders/` 送 `{request_key, warehouse, lines:[{key, packs}], payment_method, delivery_method, note}` —— **畫面填的是包數,伺服器換成片數(包數 × 一包幾片)才送給廠商**(紅隊:店員講包、API 收片,打 2 以為兩包會出兩片,又不能取消);**品名、一包幾片、單價一律用伺服器剛跟廠商要的,不看畫面送來的;價錢不送給廠商;收件與發票只用管理員設的**(畫面送什麼都不看,不然貨可以寄到任何地方);付款方式與取貨方式可以每張選;發票信箱必填(廠商那邊沒有就整張擋)。**同一張叫貨單在廠商那邊只成立一次**(規則在 `services.py` 開頭):畫面每開一張新單產生一把鑰匙(`request_key`,跟著草稿存在瀏覽器),送給廠商的那一把固定由它算出來(`pos-公司代碼-鑰匙`);**先存好叫貨單(送出中)才打廠商**;廠商明確說成立 / 409 帶單號 → 已成立;**明確被擋(4xx)→ 這一列刪掉、鑰匙可以再用**(改一改同一把再送);**沒有明確答覆(斷線、逾時、5xx、回的不是看得懂的內容)→「不確定」,只能用同一把鑰匙再送**(`POST /vendor-orders/{id}/resend/`,或畫面拿同一把再 POST)—— 成立過會拿到同一個單號。重送時只有 400 / 422 能證明先前也沒成立(廠商先查鑰匙才檢查內容),金鑰無效、太頻繁證明不了、照舊不確定;**送出之後金鑰換過就不能再用重送確認**(廠商的防重複是「金鑰 + 鑰匙」,換了金鑰同一把鑰匙會變第二張;比對 `key_fingerprint`)。廠商回的總額 − 運費 ≠ 叫貨當下的貨款 → `amount_matches=False`(畫面寫「金額與叫貨時不同」;有瑕疵補發的免費列時會這樣)。**進度**(「廠商叫貨」或「進貨入庫」有一項就可以按,2026-10-10 起):`POST /vendor-orders/sync/` 跟廠商要這個帳號最近 100 張,更新 POS 這邊的,並帶回「不是從 POS 叫的」(電話、LINE、廠商後台代下;紅隊:側門還開著,至少老闆看得到全貌)。這個功能是方便與留紀錄,**不是管得住額度**(不能改單、取消;看不到額度)。跟廠商講話只有 `standard.py` 的 `_call` 一個口(測試換掉它;自動測試不打真的廠商);哪一種回應算成立 / 沒成立 / 不知道在 `standard.Client.place()`。畫面:「進貨入庫 → 廠商叫貨」(`pages/vendor-orders/VendorOrdersPage.tsx`:叫貨 / 紀錄兩個分頁;清單可以找、只看已選;最下面固定合計與「確認叫貨」,確認頁寫幾包 = 幾片 = 多少錢)、「系統設定 → 叫貨串接」(`pages/settings/VendorLinksPage.tsx`;金鑰那一格是文字框遮成圓點,不用密碼框 —— 瀏覽器會把存過的登入密碼自動填進去),規則在 `frontend/src/lib/vendorOrder.ts`(有測試)。**第二步:到貨變進貨單**(規則在 `receiving.py` 開頭;要員工帳號的「進貨入庫」`purchase`,不是「廠商叫貨」—— 收貨的人不一定是叫貨的人):`GET /vendor-orders/{id}/receiving/` 跟廠商要這張單**現在**的明細(`GET /orders/{單號}` 的 `items`;廠商事後改單、改價就是改過的),回每一行 叫 / 已出 / 已入 / 建議這次入幾個 / 單價 / 對到哪個品號;`POST /vendor-orders/{id}/receive/` 送 `{request_key, lines:[{key, qty, product}], issue_note}` → **開一張進貨單**(既有的 `PurchaseOrderSerializer` + `commit_purchase_order`,庫存與成本的帳只有那一份)。**一張叫貨單可以分好幾次入**,一次一張進貨單;「已經入了幾個」= `VendorReceiptItem` 裡**進貨單沒作廢**的加總(進貨單作廢,那幾個自動回到還沒入);建議數量 = 廠商已出、這家店還沒入的,比已出的多只提醒不擋,比還沒入的多才擋。**先鎖住那張叫貨單才看已經入了幾個**(兩個人同時按只有一個進得去;有兩條連線的測試);跟廠商要明細在鎖之外;同一把 `request_key` 再送回同一次。**畫面按確認時先把這一次(鑰匙 + 那幾行)記在 sessionStorage 才送,拿到明確答覆才清;還記著的時候面板鎖住、只能「再送一次」**(複審:回應沒回來、關掉再開會換新鑰匙再入一次;`lib/vendorReceive.ts` 的 `pendingOf` / `pendingFrom` / `receiveOutcome`)。**再送一次被擋時只有 400 / 422 算「上一次也沒入」,401 / 403 / 404 繼續記著**(那幾種是伺服器還沒查鑰匙就擋的);**同一把鑰匙的入庫請求在伺服器排隊**(`receiving._lock_request`,advisory lock 握到整個請求結束:上一次還在等廠商時,再送的那一次要等它跑完才看有沒有入過 —— `receive()` 丟 `VendorError` 的意思必須是「這把鑰匙沒入過」,畫面靠這個決定能不能開新的一次)。**單價一律用廠商現在的、畫面送什麼都不看**;owner 2026-10-10:**成本 = 實際付出去的金額,含稅、不除 1.05** → 課稅別用「未稅」;**貨到付款的單記現金 —— 是不是貨到付款看廠商這次查單回的(`_payment`),不是叫貨當下記的**(廠商事後會改);`is_reissue`(瑕疵補發)數量照入、`billed_qty=0`。廠商回的明細**有一行看不懂就整張不給入**。**運費算不算進成本是門市的設定**(`VendorLink.freight_into_cost`,管理員設,預設算;紅隊:不能每次由入庫的人勾):2026-10-11 起**本次實付運費由收貨人明填（沒有支付填 0）**，再照各行貨款攤進成本；舊月結未帶運費才保留按比例分攤。不從入庫成本反推現金，貨到付款用伺服器計算的 `cash_paid`。**料號 → 品號**記在 `catalog.SupplierProduct`(平台 `moceo`;有規格的一格一個 `料號#spec規格編號`),查的時候走 `identity.services._vendor_sku_owner`(別名表先認領的一樣算數,這裡改不了它);沒連過的由入庫的人當場挑**既有的**品號(只收按數量管的一般商品;序號 / 中古 / 虛擬 / 停用都擋);可以事先在「對照」分頁連好(下面「品名連連看」)。供應商:`VendorLink.supplier`,沒指定就用 / 建一筆跟廠商同名的並記回串接。**不是從這裡叫的單**:`POST /vendor-orders/adopt/ {warehouse, order_no}` 認進來變 `VendorOrder(source=outside)`(明細不存),`(公司, 廠商, 廠商單號)` 唯一(共用金鑰的兩家門市不會各入一次);「不確定」的單先被認進來、之後重送確認是同一張 → 入庫紀錄搬過去、認進來的那一筆拿掉(`services._send`)。`POST /vendor-orders/{id}/issue/ {note}` 記「到貨問題」(送錯、少到的那幾行這次不入,留在單上)。`services._apply` 只寫進度那幾格(整列重存會蓋掉別人剛寫的到貨問題)。畫面:叫貨紀錄的「已入庫」欄與「到貨入庫」、`pages/vendor-orders/ReceiveDrawer.tsx`、叫貨串接的「入庫供應商」「入庫的運費」,規則在 `frontend/src/lib/vendorReceive.ts`(有測試)。已知:入庫面板裡不能當場建新品(到「對照」分頁建)。**品名連連看(第二步 2a;owner 2026-10-10:「店內品名A=供應商品名甲,指定好之後,後續下訂,只需收貨,即可直接入庫」;他選:沒有對應的可以當場建、店員都可以連與改)**:叫貨頁第三個分頁「對照」(`pages/vendor-orders/MappingTab.tsx`)—— 這家廠商**現在**的每一個品項 ↔ 店內商品,連 / 改連 / 解除;店裡沒有的當場建(「先找有沒有建過」→ 新增表單,防重複照舊;要有「商品建檔」)。規則在 `apps/vendor_orders/mapping.py`:`GET / POST /vendor-orders/mappings/`(`{warehouse, vendor, key, product}`,`product` 給 null = 解除;**清單不帶價錢**);要有「廠商叫貨」**或**「進貨入庫」其中一項、鎖在門市的只能動自己門市、門市設成只限管理員叫貨的店員照樣可以連;存的就是 `SupplierProduct`(到貨入庫讀同一份),清單用整批查法 `owners_of`(**有測試釘住它跟 `_vendor_sku_owner` 說的是同一個商品**);**品名、規格、一包幾個一律用伺服器剛跟廠商要的**,廠商現在沒有的品項不能連;別名表先認領的改不了也解除不了。**誰都能改,所以每一次改都留紀錄**:舊的那一筆停用留著,備註寫「什麼時候 誰 改對到哪個品號 / 解除對照」(`receiving._retire`)。**舊畫面不能悄悄把對照改回去、也不能把解除的連回去**:到貨入庫的每一行帶著「畫面上看到它原本對到誰」(`was`:商品編號;null / 沒帶 = 看到的是還沒對過),伺服器跟現在的對照比(`receiving._map(seen=…)`):不一樣 → 不入、對照不動(「現在對到的是…(對照剛被改過)」/「對照剛被解除」,請他重開);一樣而品號是別的 = 他按了「改」換的(或第一次挑);送來的就是現在對到的那一個不核對;連連看那一頁是明講要換、不核對(`NOT_CHECKED`)。**入庫面板上「這一行入到哪個品號」只有一個算法 `lib/vendorReceive.ts` 的 `chosen(line, draft)`:對過、沒按「改」的 → ### 只給指定公司的廠商 / kcimos 價目

### 叫貨單自動送進 kcimos

2026-10-14 起(K1b;owner:「我就是要全自動，因為kcimos叫貨看冗長的品名是地獄體驗」)。kcimos 沒有 API、POS 的網頁也不能直接對它送東西(跨網站不帶登入)→ **送單的是 POS 提供的一支 JS「kcimos 小幫手」(`frontend/public/kcimos-helper.js`),人在已經登入的 kcimos `vendor_orders/handoff.py`**:每一次送單一筆 `VendorHandoff`(`open` 發了代碼(只存雜湊、15 分鐘)→ `claimed` 開始動購物車 → `submitting` 要送了 → `done` / `failed`;放棄、過期 `dropped`);小幫手用的端點(`site-handoff/<代碼>/` 與
