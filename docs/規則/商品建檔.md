### 新增商品的預設與用詞

2026-10-06 起(依 owner 交的診斷 `docs/MP-POS-商品主檔學習成本診斷與改善方向.md` 的階段 A)。**同一種商品從哪個入口建,預設都一樣**:規則在 `frontend/src/lib/productDefaults.ts`(有測試)——主機(手機 / 平板)逐件記序號,機型配件、通用配件按數量,**維修零件(零件倉)一律按數量**(`defaultRequiresSerial`);一般「新增商品」與「新增配件 / 型號展開」都用它。一般表單換商品性質或倉別時「需追蹤序號」跟著換,**除非**在編輯既有商品(可能已經有庫存)、人自己動過那一格、或被定住(虛擬商品一定不追、中古機一定追);這幾個動作都是 `lib/productDefaults` 裡吃整份表單狀態的函式(`withNature` / `withWarehouse` / `withPin` / `withSerialByHand`),測試是整段操作(含存草稿再載回來);商品性質底下顯示「庫存:逐件記序號 / 按數量」。**一般表單新增時選「主機」不直接建**:顯示「新增手機型號 / 留在這裡建立」,沒按後者之前不能存(`phoneNeedsWizard`;只管商品倉,切到零件倉不擋)——手機 / 平板走「新增手機型號」才有容量、顏色、品況的結構;那一頁要求至少一個容量、一個顏色,沒有這些之分的機種(老人機、手錶)才留在一般表單建。編輯既有的主機不受影響。**「新增手機型號」的品況只預選「全新」**(`defaultConditionIds`:啟用中、不是中古、也不用逐台記機況的第一個;找不到就都不勾),不再全部勾起來。**用詞各只有一個意思**:全新 / 已拆封 / 中古機那一邊叫「品況」(主檔頁是「商品品況」,以前叫「商品狀態」,舊名字留在 `nav.ts` 的 `aliases`);主力現貨 / 即將換代 / 停產下架 / 清倉處理那一邊叫「販售狀態」(`lifecycle_status`)。畫面上不寫 SKU、placeholder、wizard、欄位名稱,寫「品項」「這一頁」。「中古機」的勾選在看得到的「屬性」裡(以前收在「會計處理」)。勾「虛擬商品 / 中古機」會把那一格定住(虛擬不追、中古一定追),取消時回到該回的地方(`requiresSerialAfterUnpin`),不停在被連動改掉的值上。**表單自己要記的三件事放在表單狀態裡、跟著草稿存、不送到後端**:`serial_touched`(人動過序號沒有)、`serial_before_pin`(勾虛擬 / 中古之前的值)、`phone_here`(按過「留在這裡建立」,離開主機就收回)—— 放在元件自己的記憶裡的話,存草稿再載回來就沒了,只能用猜的、會猜錯;舊草稿沒有這幾欄時的補法在 `serialMemoryFromDraft`。「新增配件 / 型號展開」的「人動過」也存在它的草稿裡。七個入口的收斂、先找再建 2026-10-07 做了(下面「新增商品先找一次」);批次貼上 2026-10-23 併進匯入表格(先選類別、按數量 / 逐件記序號一定要選);舊資料整理還沒做(`BACKLOG.md`)

### 新增商品先找一次

2026-10-07 起(新手商品建檔 R1 第一小包的第二步;owner:「不知道按哪一顆」「不確定是不是建過了」)。**商品管理上面那一排只有兩顆**:「批次工具」選單(2026-10-23 起:手機型號 / 多款展開 / 匯入表格 / 零件批次,字數一致;見「匯入表格與批次修改」那一列)+ 主要的「新增商品」。**按「新增商品」先開「先找有沒有建過」**(`pages/products/FindFirstPanel.tsx`):打品名或條碼 → Enter / 「尋找」;候選每一列有縮圖、品名(點了看照片與規格,面板上有「使用此商品」)、品號 / 類別 / 規格、庫存(0 也寫)、已停用、為什麼找到、哪裡不同;「使用這款」= 關掉並選到那一筆(右邊就有「進貨」),已停用的是「查看這款」;最下面「建立手機平板」(去新增手機型號)/「建立其他商品」(開原本的表單,找的那一句帶進品名;有候選時前面多一句「以上都不是」)。**帶進表單的規則**(`barcodeIn` / `searchText` / `createPrefill`):去掉空白與連字號後整串數字 8 碼以上 = 條碼(照包裝印的 `4712-3456-7890` 打也算;送去找與帶進表單都用那一串數字),**15 碼而且檢查碼正確的是 IMEI、哪一格都不帶**(刷了盒子上的 IMEI 找不到就建,那一台的序號會變成整個商品的條碼),其餘帶進品名;帶進來的字算在「一開始就有的」,什麼都沒改就關掉不問存草稿。**規則只有 `frontend/src/lib/findFirst.ts` 一份**(有測試;99 條「改壞會紅」):(1) **沒查成功不能當成沒有** —— 還沒找、還在找、查失敗:沒有候選、兩顆建立都不能按,寫的是「尋找中…」/「沒有查成功,請再找一次」,不是「沒有找到」;兩個查詢(共用比對 `/products/resolve/` + 片段搜尋 `/products/?search=`)都成功才算查成功。(2) **畫面上的候選一定是框裡現在這句話的** —— 每找一次換一個號碼,比較晚回來的舊回應不算;字改過了,先前的候選變淡、不能選、兩顆建立不能按。(3) **候選的順序四段**(`mergeRows`):共用比對裡強的(條碼 / 已確認叫法相同、特徵相符)→ 片段搜尋裡品名 / 規格 / 類別 / 品號 / 條碼真的有打的每一段字的(`hasEveryWord`;列上寫「字都對得上」)→ 共用比對裡只是相關的(同機型但有差異)→ 片段搜尋裡只是長得像的(寫「只是相似」;打 6 碼以上的數字時不寫 —— 片段搜尋那時候還會比每一台的序號,畫面看不出來)。`hasEveryWord`:空白、斜線、連字號分段(打的那一邊與品名那一邊都只是分隔:`SAM-NOTE5` 對 `SAM NOTE5` 兩個方向都對得上)、不分大小寫;每一段怎麼算「有」(`hasWord`,不是單純的包含):**數字要是一整段**(開頭是數字前面不能還是數字、結尾是數字後面不能還是數字:條碼中間剛好有 512 不算、`20W` 不算在 `120W` 裡、`12GB` 不算在 `512GB` 裡;`512GB`、`IP15` 裡的算;**小數是同一個數字**,`2.5D` 裡沒有 `5D`、也沒有單獨的 `2`);**英文要從一個字的開頭對起**(`S25` 不算在 `Plus 25W` 裡;後面可以還有,`pro` 對 `PROMAX`);**數字後面接的英文(單位、機型後綴)要是完整的**(`1.2M` 不算在 `1.2MM` 裡、`13P` 不算在 `13PM` 裡;例外只有同一個單位的兩種寫法 `256G` = `256GB`、`1T` = `1TB`);**數字跟單位分開打是同一段**(`queryWords`:`20 W` 併成 `20W`,不然會拿 `20V` 的 20 配旁邊 `65W` 的 W);英文與數字之間可以隔著空白 / 斜線 / 連字號(黏在一起打的 `iphone15` 對得上 `iPhone 15`);打的符號照字面比。第二段要在第三段前面(打「iphone 15 512」,同機型的保護貼有二十個,真正叫這個名字的手機會被擠到看不到);第三段要在第四段前面(打「iPhone 15 保護貼」,片段搜尋回來幾十支 iPhone,店裡寫成 `IP15` 的保護貼要先看到)。(4) **候選上的庫存算哪一家**(`stockScope`):鎖在一家門市的店員一律算自己那一家(共用比對伺服器本來就這樣回,片段搜尋與查重那一塊跟著帶 `?warehouse=`),沒鎖的算全公司。**畫面那一側**:輸入法選字的 Enter 不找(選字結束後晚一拍才放掉;「尋找」按鈕不經過這一關);**照片面板開著時下面那一個抽屜整個不能動**(`Drawer` 的 `frozen`:頁首的 ×、內容、頁尾都 `inert`;先找的框與商品表單都是)—— 不然可以用 Tab 繞回去改字、關掉重開、或看著 A 的照片按到 B 的「就是這個」;照片面板上的「使用此商品」按下去那一刻還會再核對一次(`stillUsable`:框還開著、還是同一次查詢、字沒改過),表單的儲存與「就是這個」在照片面板開著時也不做;**商品表單在儲存 / 改用既有商品進行中也整張凍住**(送出去的是按下那一刻的內容,這時候再改的字不會被存、存好又被清掉;沒存成回來時游標放回原本那一格);整理回應時出錯也算沒查成功(不停在「尋找中…」)。**存檔時「可能已經建過」那一塊**(`DuplicatePanel`,待確認入庫也用同一個):候選補上庫存與縮圖(另外跟商品要一次;還沒拿到、或這一次沒查成功都不寫庫存,不把「還不知道」顯示成 0、也不拿之前查的當現在的),商品管理裡點了可以看照片與規格。**「記住這個叫法」改成自己勾**(原本預設勾著;品名或條碼一改就收回不勾),選「就是這個」之後用訊息條講清楚記成了什麼(`rememberNote` / `rememberTone`,看後端回的 action **與那一筆叫法是不是已確認的** —— 原本就記著(kept)的可能本來只是搜尋用的字,不能看到 kept 就說會直接對到):「以後直接對到這一款」(綠)/「只幫助搜尋,不會直接對到」/「沒有記住」(紅;以前放在上面那條綠色的成功列)。能不能建仍然由存檔時的防重複關卡決定(`guard_new_product`),這個框只是讓人先看到;後端沒有動。沒做:進貨開單頁當場建品號、表單照種類簡化、待確認(R1 的第 2~4 小包);沒有照片時新增商品的重送保護(要動後端,另外一步)

### 新增商品防重複

`apps/identity/dedup.py` `guard_new_product()`:所有建新品入口都過。條碼 / 已確認叫法相同 → 409 硬擋;特徵相似 → 409,帶 `distinct_reason`(寫哪裡不同)才放行,存 `ProductDistinctDecision`。批次每列各自說明,匯入列進略過。新增入口要建 Product 一定要呼叫它。**「新增手機型號」排出來的主機另有一條**(2026-10-07,`dedup.MainUnit`;owner 要建 iPhone 17,40 列每一列都被要求說明):主機是照「機型 × 品況 × 容量 × 顏色」一格一個品號排的,所以相似的候選只留「可能真的是同一台主機」的 —— **配件不算**(皮套就叫 `IP17/黑`。認法:**不追蹤序號、品名與規格裡也沒有寫容量** —— 精靈排的主機一定有容量;放在哪個類別不管,有的店配件就建在手機類別裡;「有沒有寫容量」連它的其他叫法一起看(`MatchContext.states_capacity`:靠一個寫了容量的叫法對上的就是有寫);**這一條只在這一列「容量那一格」填的認得出來時才用**(只看那一格,不看整串品名 —— 後綴或顏色裡剛好有 `8GB` 不算):容量欄打 `256`(沒單位)、`1024G` 這種認不出來的寫法時不排除配件,不然同樣寫 `256` 的既有手機會被當成配件漏掉)、**另一個品況不算**(「中古機」與「中古機(保固內)」本來就是兩個品號;同一批裡品況不同的兩列也不互相算);同一個品況裡的重複(顏色寫了「藍」又寫「藍色」)、沒記品況的舊品號、追蹤序號的商品(不管在哪個類別、有沒有寫容量)、**不追蹤序號但寫了容量的**(`iPhone 17 256G 黑`:多半是以前用一般表單建錯的手機)照樣提醒。先篩掉這些才取前五個候選(不然五個名額被配件佔滿,真正重複的手機看不到)。條碼 / 已確認叫法 / 同名的硬擋不受影響;別的入口(一般表單、批次、匯入)照舊

### 商品表單的順序與分頁

2026-10-24 起(全站檢視 D3、D4)。**新增 / 編輯商品**:主畫面只有品名、類別、廠牌、相容機型(機型配件)、條碼、售價,下面一行寫「商品性質 · 庫存怎麼記(· 中古機)」;倉別、商品性質、規格、業務員成本、販售狀態、屬性勾選收在「更多」(每一格都有預設;伺服器退回這幾格的錯誤時自己打開)。新增時游標停在第一個沒填的必填格(品名;帶了品名就到類別),編輯不搶游標。**商品性質照類別主檔的種類帶**(`lib/productDefaults.ts::natureOfCategoryKind`:主機 → 主機、配件 → 機型配件、一般 → 通用配件,不看類別名稱 → 類別的種類要設對):只在人換類別、或「新類別」建好選用時;人自己在「更多」按過商品性質就不再替他改(`nature_touched`,跟著草稿走、不送出去);零件倉不帶;編輯時用過的商品不帶。「再建一個」沿用類別、商品性質、廠牌。**分頁**:新增商品、新增手機型號都從商品管理另開分頁(瀏覽器擋住就在原頁換頁);存好通知原本那一頁(`lib/productTabs.ts`,postMessage、只認同一個網站)清單重抓並選到那一筆,「回商品頁」/「商品列表」關掉這一頁回原本那一頁;原本那一頁不是商品管理(盤點、進貨開的)、已關、直接打網址進來的照舊在這一頁換頁

### 新增手機型號先從型號庫選

2026-10-24 起(全站檢視 D10)。精靈第一步 `pages/products/DeviceLibraryStep.tsx`:`GET products/device-library/?search=`(平台型號庫裡每個字都對到品牌或型號的,最多 30 支,帶這家公司已經建了幾個品項)→ 已建的只給「去看」(商品管理搜那一支,不再建第二套)、還沒建的「建立」先預覽(`POST products/device-library/build/ {uid, preview:true}`:會建幾個、各品況幾個)再確認;**建的規則就是每天自動建品號那一套**(`device_expand.expand(tenant, uids=[uid])`:名稱、品況、容量顏色全照型號庫,不給勾掉;公司已經對到這一支 → 400)。型號庫沒有寫「型號庫沒有這支」,「手動建立」走原本那三步(水貨、舊機;預覽照舊會標出可能重複、要寫差異)。**展開時公司這個機型已經有的「容量 × 顏色 × 品況」不再建**(品名被人改過也算有;複審 P1,每天自動建品號一起受益)。要有「商品建檔」

### 手機精靈的建議售價
