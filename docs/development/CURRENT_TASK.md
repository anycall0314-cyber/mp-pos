### 目標

同一個商品不管從哪個入口建,欄位、預設、存下去的結構都一樣;普通配件不會意外被要求逐件記序號;畫面上不出現互相矛盾或要懂程式才看得懂的說明。

### 文件點名、我對照程式確認成立的(候選項目,還沒定案)

1. **序號預設不一致**:一般「新增商品」預設勾著「需追蹤序號」(`ProductForm.tsx` 的 `EMPTY`),專用的「新增配件」同一種商品卻沒勾(`ProductExpanderModal.tsx`)。
2. **手機從不同入口建,結構不一樣**:一般新增選主機,沒有手機精靈的容量 / 顏色 / 地區 / 品況那些結構化欄位。
3. **手機精靈預設把所有品況全勾**(`NewPhoneModelWizardPage.tsx`):新手一按就建出用不到的組合。
4. **「狀態」兩套意思**:商品表單的「商品狀態」= 主力 / 換代 / 停產 / 清倉;手機精靈的「狀態」= 全新 / 拆封 / 中古;中古另外藏在「會計處理」。
5. **互相矛盾、工程用語的說明**:精靈第一步寫「配件 placeholder SKU」、第二步又說不建配件品號;畫面出現 `is_secondhand=True`、SKU、wizard。
6. **「系列」與「後綴」重疊**:APPLE 的系列選項有 `PRO`、`PRO MAX`,同頁的後綴又拿 Pro / Pro Max 當例子。**這一項是資料(系列字典)的問題,要 owner 確認正式的機型與系列清單,我不能自己猜。**
