### 第二步:先找再建(2026-10-07 展開;只動畫面,後端不動)

做法(規則只有 `frontend/src/lib/findFirst.ts` 一份,有測試):

1. 商品管理上面那一排只剩兩顆:「批次工具」選單 + 主要的「新增商品」。
   選單六項字數一致:手機型號 / 配件展開 / 型號展開 / 零件批次 / 批次貼上 / 匯入表格(原本的七個入口一個都沒拿掉)。
2. 按「新增商品」先開「先找有沒有建過」(`pages/products/FindFirstPanel.tsx`):打品名或條碼 → 按 Enter 或「尋找」。
   候選 = 共用比對(`/products/resolve/`)在前 + 品號 / 條碼 / 品名片段(`/products/?search=`)補在後;
   每一列:縮圖、品名(點了看照片與規格)、品號 / 類別 / 規格、庫存(0 也寫)、已停用、為什麼找到、哪裡不同。
   「使用這款」→ 關掉、選到那一筆(右邊就有「進貨」);已停用的是「查看這款」。
   最下面兩顆:「建立手機平板」(去新增手機型號那一頁)、「建立其他商品」(開原本的表單,找的那一句帶進品名;整串數字 8 碼以上帶進條碼)。
3. **沒查成功不能當成沒有**:還沒找、還在找、查失敗 → 沒有候選、兩顆建立都不能按,畫面寫的是「尋找中…」/「沒有查成功,請再找一次」,不是「沒有找到」。
   兩個查詢都成功才算查成功。
4. **舊結果不能拿來用**:比較晚回來的舊回應不算;框裡的字改過了 → 先前的候選變淡、不能選、兩顆建立不能按,要再找一次。
5. 存檔時「可能已經建過」那一塊:每個候選補上縮圖與庫存(另外跟商品要一次;還沒拿到不寫庫存),點了可以看照片與規格。
6. 「記住這個叫法」改成自己勾(原本預設勾著);選「就是這個」之後講清楚:「以後直接對到這一款」/「只幫助搜尋,不會直接對到」/「沒有記住」。
7. 候選上的庫存:鎖在一家門市的店員一律算自己那一家(共用比對本來就這樣回,另外兩個來源跟著帶),沒鎖的算全公司。
8. 候選順序四段:強的 → 字都對得上的 → 同機型但有差異的 → 只是相似的(後兩種片段搜尋的列上有寫是哪一種)。
9. 條碼照包裝印的打(有空白、連字號)也算條碼;刷到手機的 IMEI 不帶進條碼那一格。
