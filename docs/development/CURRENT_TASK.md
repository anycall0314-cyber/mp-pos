## 新手商品建檔 R1 第二小包:進貨時找不到當場建

依據:`docs/MP-POS-新手商品建檔與既有品號沿用_完整改善計劃.md`(§6 共用流程、§10 進貨串接);R1 切成四小包,這是第 2 包。
第 1 包(找得到 + 先找再建)2026-10-07 已上線,這一包沿用它的「先找有沒有建過」。

### 目標

人在進貨開單頁刷到 / 打到一個系統裡沒有的商品,不用離開這張單去「商品管理」:當場先找一次、確定沒有就建,建好(或找到既有的)直接回到這張單的明細上。
進行中的明細、「沒加入」的其他碼都不能因此不見;同一趟不會被加兩次。

### 做法(只動前端;後端不動)

1. **掃碼框多一個「建立」的入口**(`components/workbench/ScanBox`,只有頁面有給 `onCreate` 才出現;銷貨、調撥、中古收購不變):
   - 下拉最下面多一列:有候選時「都不是,建立商品」、沒有候選時「建立商品」(滑鼠點,或上下鍵移到那一列按 Enter)。
   - 「沒加入」那一排:因為**找不到 / 相似的太多 / 不是完全相同**而沒加進去的那幾筆,旁邊多一顆「建立」。
     其他原因(已停用、這張單已經送出、那一台在別的地方、連線錯誤)沒有這一顆 —— 那不是「沒建過」。
2. **按了先開「先找有沒有建過」**(第 1 包的 `FindFirstPanel`),帶著剛剛那串字、自動先找一次(用這張單的廠商;一般進貨不列中古機)。
   - 「使用這款」→ 那個既有商品加進這張單;
   - 「建立其他商品」→ 原本的新增表單(字帶進品名 / 條碼),存好之後加進這張單;存檔被防重複擋下選「就是這個」也是加那一個既有的;
   - 「建立手機平板」→ 去「新增手機型號」那一頁(這張單的草稿留著;那一頁建完按「前往進貨」會帶回來 —— 第 1 包之前就有的)。
3. **加進這張單 = 跟從下拉挑到它一樣**(走同一支 `addProduct`):配件 +1、序號商品回到那一行等刷序號。
   帶回來的是中古機 / 虛擬商品 / 已停用的 → 不加,講原因,那一筆「沒加入」留著。
4. **那一筆「沒加入」跟著劃掉**(由哪一筆開始的就劃哪一筆;從下拉開始的,輸入框裡那串字清掉)。一趟只帶回一次(連按兩下不會加兩件)。
5. 這張單鎖住(儲存中 / 送出結果不明)時不能開;開著的時候背後整塊不能動。

  所以賣出去之後才把屬性改掉,之後作廢 / 退貨那張單時庫存會加減錯(按數量賣的,改成序號制之後作廢:數量加不回去)。

- 類別勾「中古機類別」會把底下**所有**商品一起改成中古機 + 追蹤序號(`Category.save`),不管那些商品用過沒有。

### 怎麼做(規則 owner 2026-10-07 確認)

1. **「用過」的定義**:有任何**沒作廢**的單據明細(進貨 / 銷貨 / 銷退 / 調撥 / 維修領料 / 待確認入庫),或有沒作廢的序號,或任何門市的庫存數量不是 0。
   作廢的單不算 —— 這就是改錯的出路:把那幾張單作廢、庫存回到 0,就可以改。
2. **沒用過**:「需追蹤序號 / 中古機 / 虛擬商品」隨便改(現在的行為)。
3. **用過**:這三個屬性**擋下來,講原因與出路**(owner 2026-10-07 選的;另外兩個選項是「帶著轉」「只提醒不擋」)。
4. 換類別如果會連帶把商品變成中古機(新類別是「中古機類別」),照同一條規則。
5. 類別勾「中古機類別」:底下有用過、而且會被改到的商品 → 照同一條規則(不能悄悄把賣過的商品改成中古機)。
6. 編輯表單打開時就讓人看得到(那三格鎖住 + 一句原因),不是等按儲存才被退回;伺服器存檔時再擋一次(以伺服器為準)。
7. 品名 / 規格 / 條碼 / 類別(不連動中古機的)/ 售價 / 販售狀態照舊可以改。
