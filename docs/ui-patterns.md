# UI 版型規約

> 對應 [decisions.md](decisions.md) 內「UX 模式 — 三種頁面版型」決策。所有業務頁面都應落入下列三種版型之一,不要混搭。

## 為什麼需要三種版型

舊系統「歐睿手機玩家 / 歐睿創意POS」在實務上是兩個介面分工：

- **後台（IE 桌面程式）**：錄入單據（進貨/銷貨/調撥/維修),鍵盤為主,以「資料錄入效率」為導向
- **前台（網頁）**：100+ 個查詢報表,以「資料檢索與輸出」為導向

新系統把這兩種模式 + 主檔維護合併到同一個 React app,但 UI 版型必須分清楚,否則：

- 用 Master-Detail 套錄入頁 → 業務員一筆銷貨要點 30 次滑鼠,慢
- 用 Master-Detail 套報表頁 → 沒篩選列,看不到日期區間/倉庫切片
- 用錄入頁版型套主檔 → 用滑鼠瀏覽商品清單變得困難

## 三種版型總覽

| 版型 | 用途 | 特徵 |
|------|------|------|
| [Master-Detail](#master-detail) | 主檔維護 | 左列表 + 右詳情,鍵鼠混用 |
| [EntryForm](#entryform) | 開單據 | 上方單頭 + 中央明細,鍵盤連續錄入 |
| [Workbench](#workbench工作台) | 拿條碼槍連續做的單據(調撥、庫存查詢) | 一個畫面:單頭卡 + 掃碼框 + 明細 + 最近的單,不開彈出視窗 |
| [ReportPage](#reportpage) | 查詢報表 | 上方篩選 + 中央結果 + 下方總計與匯出 |

---

## Master-Detail

主檔資料維護（商品、類別、倉庫、供應商、客戶等）。已有實作於 `frontend/src/components/master-detail/MasterDetail.tsx`。

### 版型

```
┌──────────────────────────┬────────────────────────────────┐
│ 篩選列                    │ 詳情頁籤（基本 / 序號 / 歷史） │
│ [搜尋框] [類別▾] [啟用▾]  ├────────────────────────────────┤
├──────────────────────────┤                                │
│ 列表表格                  │ 詳情內容                       │
│ ▷ A001 ...                │ 品號:     ...                  │
│ ▷ A002 ...                │ 品名:     ...                  │
│ ▶ A003 ...  ← 選中         │ 規格:     ...                  │
│ ▷ A004 ...                │ ...                            │
│                          ├────────────────────────────────┤
│                          │ [編輯] [刪除] [儲存]            │
└──────────────────────────┴────────────────────────────────┘
```

### 規約

- 左欄寬度可拖,預設 380px,記在 localStorage
- 列表表格用虛擬滾動（資料量大時）
- 詳情頁籤至少 1 個,最多 6 個
- 右下角操作列按鈕固定底部
- 點選左欄列即時切換右欄,不需「載入」按鈕
- 適用頁面：商品 / 類別 / 倉庫 / 供應商 / 客戶 / Carrier / TelecomPlan / Brand 等所有主檔

## EntryForm

開單據（進貨、銷貨、調撥、借出、維修單）。**業務員每天用得最頻繁,效率最關鍵**。

### 版型

```
┌────────────────────────────────────────────────────────────┐
│ 工具列:[F2 編輯] [F5 過帳] [F8 刪除] [F10 存檔] [ESC 取消] │
├────────────────────────────────────────────────────────────┤
│ 單頭:                                                       │
│ 單號  PO-000001 (自動)      供應商 [SUP001 蘋果經銷    ▾]  │
│ 倉庫  [TPE-01 台北旗艦店▾]  日期   [2026-05-17]            │
│ 業務員 [JB00 蔡樂雅      ▾]  備註  [____________]           │
├────────────────────────────────────────────────────────────┤
│ 明細:                                                       │
│ # │品號     │品名         │數量│單價   │金額   │IMEI 清單  │
│ 1 │PH-000001│iPhone 15 Pro│ 3 │27,000 │81,000 │[掃碼...]  │
│ 2 │PH-000002│iPhone 15 Pro│ 2 │27,500 │55,000 │[掃碼...]  │
│ 3 │[輸入 SKU 自動帶...]                                    │
├────────────────────────────────────────────────────────────┤
│ 附加費用:[3,000]   貨款小計:136,000  總額:139,000          │
└────────────────────────────────────────────────────────────┘
```

### 規約

- **鍵盤導航**：所有 input 用 `tabIndex` 從上到下排好,Tab/Shift-Tab 移動,Enter 進入下一格
- **F-key 工具列**：F2 編輯 / F5 過帳 / F8 刪除目前列 / F10 存檔 / ESC 取消當下動作回上一層
- **商品快查**：在「品號」格輸入 SKU 開頭或品名,顯示下拉建議,Enter 帶資料 + 自動跳到「數量」
- **條碼掃描連續輸入**：「IMEI 清單」欄位 focus 時,掃一台→自動寫入 + 自動到下一個空格,掃滿 `qty` 自動跳下一行
- **金額自動算**：unit_price × qty = amount,即時更新
- **過帳鍵 (F5)**：彈出確認 modal「確定過帳?過帳後不能修改」,確認後鎖定整單
- **單頭與明細的視覺分區**：用 border 與背景區分,讓眼睛不會在 30 個欄位裡迷路
- **適用頁面**：進貨單 / 銷貨單 / 銷退單 / 調撥單 / 借出單 / 維修單 / 中古機收購單

### 銷貨單的電信欄位

銷貨明細的電信欄位（SIM / 門號 / 方案 / 佣金 / 上線日）**預設折疊**,商品需要綁門號時點「展開」才出現,避免一般銷貨被欄位淹沒。

## Workbench(工作台)

2026-10-05 起的第四種版型,給「拿著條碼槍連續做」的單據用。目前:調撥、庫存查詢、進貨、銷貨(後兩個 2026-10-06)。

### 版型

```
┌──────────────────────────────────────────────────────────┐
│ 卡片:單頭欄位排一排(分店、日期、備註…)                    │
│       [ 掃碼框:掃條碼 / IMEI,或打品名 ]  合計  取消  確認  │
├──────────────────────────────────────────────────────────┤
│ 明細:商品 | 數量 | ✕ | 序號小標籤(後 6 碼,點選)          │  ← 新的一行在最上面
├──────────────────────────────────────────────────────────┤
│ 最近的單:點一列展開明細;要做的事直接在列上按               │
└──────────────────────────────────────────────────────────┘
```

### 規約

- 一進來就能做事:游標在掃碼框,不用先按「新增」。清單、新增、待處理併在同一頁(調撥、庫存;進貨與銷貨明細多,拆成清單頁 + 開單頁,見下面)。
- **不開彈出視窗**。要確認的動作用 `ArmButton`(第一次按換成「再按一次」);可以反悔的動作直接做,用 `toast` 給「復原」。
- 掃碼框用 `ScanBox`:`onScan` 先看是不是設備的碼(回一句話 = 認得但不能加,會留在「沒加入」那一排),不是才當商品找;
  自動加入只收「品號 / 條碼完全相同」,或人看著下拉按 Enter。會影響查詢結果的條件(例如調出分店)一變,要換 `resetKey` 讓舊的查詢作廢。
- 按了 Enter 卻沒進明細的碼一律記在掃碼框下面的「沒加入」(規則在 `lib/scanMissed.ts`,有測試):不靠輸入框記、同一個碼失敗幾次記幾筆、
  只有同一個碼後來加成功或人按「清掉」才消失;有紀錄時單據不能送出。`onPick` 回一句話 = 沒加成,也會記進去。
- **不替人選是哪一台**:只有刷到那一台的碼、人點小標籤、人用滑鼠從下拉點了商品且只剩一台,才選起來。
- 非同步的東西(查設備、載序號)回來時要確認條件沒變(門市還是同一家)才能寫回畫面。
- 送出分兩段:先等掃碼框把已經按了 Enter 的碼處理完(`scanApi.idle()`)、而且「沒加入」是空的(`scanApi.missed()`),才定要送的內容;
  從按下確認到結果回來,會改到這張單的控制項全部停用。伺服器明講不行(4xx)才算沒成立;斷線 / 5xx 算「不知道」,要回頭認單,不能直接讓人重送。
- 序號用小標籤,不另開側欄;點完標籤游標要回掃碼框。
- 樣式一律用 `.wb-*`(`styles.css` 最後一段),顏色走 `--wb-*`,日 / 夜間各一組。零件在 `components/workbench/`。
- 門市用下拉(門市只有幾家),並記住上次選的。
- 送出時帶一把鑰匙(`Idempotency-Key`,每開一張新單換一把;進貨、銷貨已接):結果不明時不用回頭猜有沒有成立,拿同一把「再送一次」就好。
  結果不明的那段時間整張單鎖住(改了內容再用同一把送,伺服器回的會是改之前那一張),只能再送一次或取消。
- 工具(勾選商品、批次貼上這種)放在頁面裡的面板,不開彈出視窗:沿用的舊元件加 `inline`。
- 就地新增(客戶、會員)不離開這一頁:開單頁用右邊的抽屜。

### 開單頁(新增銷貨單 / 新增進貨單):商品明細優先

2026-10-06 起,進貨與銷貨拆成兩頁:**清單頁**(`/sales`、`/purchases`,有頁面上方的分頁;最近的單、點一列展開、列印 / 銷退 / 調撥 / 作廢)
與**開單頁**(`/sales/new`、`/purchases/new`,整個畫面留給明細,不放分頁,頁首有「返回列表」)。
一次開很多品項、連續掃碼時,時間都花在明細;每張單只設定一次的東西不該一直佔著幾百像素高。

```
新增銷貨單                             草稿已存   返回列表   更多      ← 48
出貨倉 [民生店]  客戶 [    ] 新增  會員 [    ] 新增   [單據資訊 ▾]    ← 52
[ 掃品號 / 條碼 / IMEI,或打品名搜尋商品                          ]    ← 52
────────────────────────────────────────────────────────────────
商品            序號／門號        數量    單價    金額              ← 表頭 40,黏在最上面
              明細:吃掉剩下的高度,自己捲(新的一行在最上面)
────────────────────────────────────────────────────────────────
12 種／38 件   未稅 / 稅   毛利   還缺什麼        含稅總額  [結帳]    ← 64,固定
```

- **高度**:在 1370 × 656 的內容區,656 − 48 − 52 − 52 − 40 − 64 = 400,一列約 48px,看得到 8 列(實測 399px、8 列)。
  **字不縮**(正文 16px)、常用控制項 44px。每一排的邊框與內距算在自己的高度裡,外層不再加 margin。
  版面是 `.wb.ws`(grid:`auto minmax(0,1fr) auto`),明細那一塊 `min-height:0; overflow:auto`,桌面上整頁只有它在捲。
  矮的 / 窄的 / 放大 200% 的畫面(`max-width:900px` 或 `max-height:560px`)回到整頁自然捲動,底列黏在最下面,不硬守 8 列。
- **常駐的**:交易對象與倉庫(有欄位名稱,不靠提示字)、掃碼框與加商品的工具、總額與唯一的主要按鈕。
- **收起來的**:課稅別、發票、統編、業務員、付款方式(進貨)、備註 → 右邊的「單據資訊」抽屜(`Drawer`,440px),要改才打開。
  資料都在這一頁的 state,抽屜只負責顯示與編輯,關掉不會不見、明細與捲動位置不動。按鈕上寫著目前的計價 / 開票摘要、「有備註」、
  「待完成 N 項」(沒填的必填);**這種發票沒有可用的字軌**(結帳會被伺服器擋)也直接寫在按鈕上(「開票設定待處理」)。
- **清空草稿**在頁首的「更多」(`MoreMenu`),兩段式,跟掃碼框、主要按鈕隔開。
- **游標**:右邊那一塊關掉、門號欄位填完,游標都回掃碼框(不停在按鈕上:條碼槍的 Enter 會把它再按一次)。
  要「畫面更新完游標到某一格」用 state + effect(`focusOn`),**不要用計時器**:視窗在背景時計時器會慢一秒,那一秒打的字會跑到別格。
- **條碼槍的 Enter 不會存檔 / 結帳**:儲存、結帳、確認結帳都要人按按鈕;結帳那一塊打開時游標放在那一塊本身(不是按鈕、也不是掃碼框)。
  「確認結帳」剛好出現在「結帳」的位置,打開 0.6 秒內的那一下(滑鼠連點)不算。
- **底列的「還缺什麼」**可以點:帶人到那一格(客戶 → 客戶欄;業務員 / 發票 → 打開單據資訊停在那一格;門號欄位 → 那一行那一格)。
- 數量框用 `QtyInput`:打到一半不會被改掉(範圍內才生效,離開時不在範圍內就改回原本的數字)。
- 鑰匙(`Idempotency-Key`)、「送出去了還不知道結果」、**送出去的那一份內容**、付款方式都跟著草稿存:重新整理、切到別頁再回來
  還是同一把鑰匙、而且鎖著(只能「再送一次」或「放棄這張」;放棄之後不給復原)。**「再送一次」原樣送當初那一份**(`sentRef`),
  不照現在的畫面重新組、不重新檢查:第一次其實成功了的話,那幾台已經是「已售出」,照現在的在庫重新檢查會被自己擋住。
  用同一把鑰匙送回來的是已作廢的單 → 講出來、明細留著、換一把新鑰匙。
- 銷貨:會員上次成交價是背景查的,按「結帳」與「確認結帳」都會先等它回來(最多幾秒,沒回來就請人再按一次);
  定稿之後、或已經是下一張單,晚到的價格不再改明細(畫面上的總額要跟送出去的那一份一樣)。
  **會員換了(選了、換成另一位、清掉)或草稿還原回來,每一行都重新看**:沒有手改過的單價先回到建議售價
  (不留上一位會員的成交價),再查現在這位會員的。

#### 進貨(`PurchaseWorkbenchPage`;清單 `PurchaseListPage`)

- 常駐:供應商、入庫倉。單據資訊:課稅別、廠商發票號碼 / 日期、付款方式、備註。單據日期一律今天,不給改。
- 工具列:掃碼框、「每台兩碼」、勾選商品、批次貼上(後兩個是明細上方的面板,沿用的舊元件加 `inline`,不開彈出視窗)。
- 欄位:商品 | 規格 | 進貨數量(含贈品)| 計價數量(只算要付錢的)| 序號 | 單價 |(含稅的單才有)未稅單價 | 金額。
- 掃碼框同時收「商品」與「設備的碼」:刷到品號 / 條碼完全相同的是商品(配件同款數量 +1,**不動正在刷序號的那一行**;序號商品回到那一行);
  其他長得像設備碼(大寫英數、6 碼以上)而且找不到商品的,放進「正在刷序號的那一行」(左邊有藍線),滿了自動多一台。
  **檢查碼正確的 15 碼(真的 IMEI)不交給商品搜尋**:商品搜尋會用序號找,作廢重開的那幾台會列出商品,整批重刷會每一刷都變成「不是完全相同」。
  其他 14~16 碼數字(外箱條碼比主檔多一位那種)找得到相近的商品時照舊交給下拉,不塞進序號格。
  三個查詢(這一頁的商品、系統裡有沒有這一台、另一種模式的商品)各自看成敗:要放進序號格之前後兩個一定要有答案,查不到就不放、請人再刷。
  已經在系統裡的碼、這張單已經有的碼、這一頁不能進的商品的品號(一般進貨刷到中古機)不放,記在「沒加入」。
  規則在 `lib/deviceCodes.ts` 的 `placeScannedCode`(有測試);掃碼框刷到檢查碼不對的 15 碼放 IMEI 格(畫面會提醒),不佔掉 SN。
- 序號那一格寫完成度「已刷 3／5」(刷不滿是紅的),點一下攤開每一台的格子(`SerialSlots`);收起來照樣接掃碼框刷的碼。
  **改數量不會丟掉已經刷的碼**(`resizeUnits`:數量不能比已刷的台數少,要少一台按那一台的 ✕)。
- 勾選商品 / 批次貼上遇到已經在明細裡的商品(一個商品一行):**併進原本那一行,數量加上去**(原本 3 台、這次 2 台 = 5 台;
  序號商品原本還沒刷的空位留著,帶來的每一個新序號多一台)。不拿這次的序號去補原本的空位:補錯了會悄悄少進幾台。
  單價:勾選商品沒有單價,用原本那一行的;批次貼上每一列都有單價(寫 0 就是 0),跟原本那一行不一樣就**不併、也不丟**,
  列在明細上方那一條請人處理。有沒有帶單價由工具明講(`appendLines(fresh, priced)`),不是看數字是不是 0。
  這張單已經有的碼不重複放,沒放的碼也列在那一條(要按「知道了」才收,不是一閃就過的訊息)。
  勾選商品 / 批次貼上加進序號商品之後,「正在刷的那一行」換到它(不然接著刷的碼會進舊的那一行、還替它多加一台)。
- 刷到 / 選到已停用的商品:**不算加進去了**,那個碼記在「沒加入」(有那一筆就不能儲存:不然東西進店了、單上卻沒有它)。
  管理員可以在訊息條按「恢復」,恢復之後再刷一次才加進明細。
- 計價數量:跟進貨數量一樣(沒有贈品)時兩個一起動(掃到多一台、刪一台都是);人另外設了贈品數才照他設的。**0 = 整行贈品**。
- 草稿記著「正在刷的那一行」:重新整理回來接著刷,不用先點那一行。
- 掃碼進明細看的是「定稿了沒」(`frozenRef`),不是「鎖住了沒」:按了儲存要先等還在查的碼做完(那幾筆照樣加得進去),
  等完才定稿;定稿之後才到的碼回一句話、記在「沒加入」,不會悄悄少一件。
- 儲存 = 建單並入庫,一下就送;存完回清單頁,那一張展開著(列印標籤、整張調撥、作廢都在那裡)。
- 嵌在中古收購頁(`mode="secondhand-vendor"`)時沒有自己的頁首,「更多」放在供應商那一排,存完不離開。

#### 銷貨(`SalesWorkbenchPage`;清單 `SalesListPage`)

- 常駐:出貨倉、客戶(必填)、會員(各有「新增」,在右邊的抽屜填)。單據資訊:發票類型、課稅別、發票號碼(只讀)、買受人統編、業務員、備註。
- 欄位:商品 | 序號／門號 | 數量 | 單價 | 金額。
- 序號商品:選好的那幾台直接排在同一列(後 6 碼小標籤);在庫的每一台只在「攤開的那一行」列出來(同一時間最多一行,
  剛加進來還沒選台的會自己攤開),其他行都是一列。逐台定價的商品(已拆封 / 中古)一列一台:換一台帶那一台自己的售價,
  把那一台點掉單價回到建議售價(不留前一台談好的價錢)。
- **門號商品**(虛擬商品、可以填門號;照 owner 自己做的 Ored 套件):門號、方案、卡號、合約日期**緊接在那個商品正下方一排**。
  加進來游標直接到門號,Enter → 方案 →(新辦 / 攜碼)卡號 →(攜碼)合約生效日 → 回掃碼框。
  一個門號一列,不併數量。還沒填的在品名旁標「待填門號 / 待選方案 / 待選卡號 / 待填生效日」,那一行左邊一條提醒色,點一下游標到那一格。
  新辦、攜碼才要卡號;續約只要門號與方案。**合約從起算日算**:新辦當天、攜碼填合約生效日、續約是「續約日」(預設今天,
  遠傳 / 台哥大不用動;中華電信等手機到貨才續約的往後改)。旁邊試算合約到期日(`lib/dates.ts`,跟後端同一套)。「原合約到期」是續約選填的記錄。
- 門號商品數量固定 1(伺服器也擋:有方案的那一行數量只能是 1);同一張單同一個門號出現兩次不能結帳;單價、拆帳金額不能是負的。
- 右邊那一塊開著的時候,背後整塊 `inert`(點不到、游標進不去):結帳畫面開著,下一槍條碼不會加進明細把應收改掉。
- 結完帳的那一張不跟著抽屜消失(點到外面、Esc 都會關抽屜):底列留著「上一張 SO-… 列印收據」,下一張開始加商品才收掉。
- 草稿記的付款方式如果已經停用,不替人改選別種,請他重選。
- 換出貨倉:有明細時先問(明細是照原本那家的庫存加的,換了要清空),不悄悄清。
- 底列:幾種幾件(種 = 不同的商品)、未稅 / 稅、毛利(可遮)、還缺什麼、含稅總額、「結帳」。結帳在右邊的抽屜:
  付款方式(一排小標籤,點一種 = 那一種收全額;要分開付按「拆帳」逐格填)、「確認結帳」;結完同一塊留著列印收據 / 發票、繼續開單、返回列表。
- 清單頁點一列展開:列印收據 / 發票、整張銷退(帶著原單到銷退頁)、作廢(兩段式;被擋的原因留在那一列上)。銷退單清單在分頁「銷退單」。
  門號那一行有「改日期」(續約、攜碼;新辦當天生效沒有):續約日往後延(中華電信先入帳)或當初打錯,就地改,
  合約到期日用那一張當初的綁約月數重算;作廢的單不能改。

## 商品照片的入口(點品名看照片與規格)

零件在 `components/photos/`。原則:**看照片是「看」,不是「選」**;入口不佔版面、不改原本的手感。

- 頁面最外層放一個面板:`const peek = usePhotoPeek(關掉之後要做的事)`,在畫面最後放 `{peek.panel}`。
- 品名用 `<PhotoName id name sku thumb onPeek={peek.open} />`:品名本身可以點;有照片(`photo_thumb`)才多一個 32px 小縮圖。
  縮圖用負的上下外距,**不能把那一列撐高**(開單頁、清單頁的列高不變)。點了不會展開那一列、不會加進單據。
- 掃碼框的搜尋下拉:選項帶 `peek: "照片 N"` 才會多一顆小按鈕,頁面接 `onPeek(opt, use)` 開面板並把 `use` 交給面板的「使用此商品」。
  點下拉的品名仍然是選用;看完按「返回繼續找」→ 呼叫掃碼框的 `resume()`,游標回輸入框、原本的搜尋結果還在。
- 已經在明細裡的商品只給「關閉」,不給「使用此商品」(不然會重複加)。
- 主檔頁(Master-Detail)點那一列照舊是選取;詳情裡用 `<ProductPhotoStrip productId />` 放一排照片,清單的小縮圖才開面板。
- 表單裡加 / 改照片用 `<PhotoSection photos={usePhotoDraft(...)} />`:照片先掛在這一次編輯上,存檔時把 `photos.payload()` 跟表單一起送;
  存檔前 `await photos.beforeSave()`、成功 `photos.saved()`、失敗 `photos.saveFailed()`、不存了 `photos.cancel()`。

- **儲存查詢**：常用篩選組合可命名儲存（例:「本月在庫 iPhone」）, 第二次點直接帶條件

- 新增報表時不用改前端代碼

## 共通約定

### 金額

全站金額一律**整數元、四捨五入**,畫面上不出現小數點(owner 2026-10-06)。

- 顯示:`money(v)`(`@/lib/money`)—— 整數 + 千分位;資料庫給的 `"1500.00"`、算出來的 `952.38` 都直接丟進去。
  不要自己寫 `Math.round(...)` / `Number(x).toLocaleString()` / `toFixed(2)`(`money.test.mjs` 會掃到)。
- 輸入框:`<MoneyInput value onChange />`(`@/components/MoneyInput`)—— 小數點打不進去、貼上帶小數的會四捨五入、
  資料庫的 `"1500.00"` 顯示成 1500、沒有上下箭頭。`onChange` 直接給字串。不受控的框(按 Enter 才取值、離開才存)用 `defaultValue`。
- **表單載入時把資料庫原本的字串直接放進 state,不要先 `intStr()`**;送出時照 state 送。使用者動過的值一定是整數,
  沒動過的原樣送回去 —— 以前存的 100.50 只改備註不會被改成 101,成本 95.24 也不會被收掉。
  表單本來就會自己整理金額的(雜支、現金調整)用 `keepOrInt(現在的值, 載入時的值)`。
- 新增的資料、要拿來算的數字:`intStr(v)` / `roundInt(v)`。一行明細的金額用 `lineTotal(數量, 單價)`。
- 看已經存好的單(唯讀):頁尾的小計 / 稅額 / 總額與每行金額直接顯示存下來的數字,不要重算。
- 開單頁試算未稅 / 稅額 / 總額:`splitTax(每行金額, 課稅別)`,跟伺服器存檔同一套算法。
- 不是金額的數字不受這條限制:賣出速度(件 / 日)、比率(%)。

### 顏色與裝飾

- 狀態文字(警示 / 成功 / 錯誤 / 資訊)與它們的外框一律用 `styles.css` 最上面的變數:`--warn-text`、`--success-text`、`--danger-text`、`--info-text`(各有 soft / orange 等變體)。
  夜間是亮色、日間自動換成白底上看得清楚的深色。不要直接寫 `#fbbf24` / `#4ade80` / `#ff7070` / `#60a5fa`(日間白底上對比只有 1.7~2.7)。
  純底色的小圓點、色條可以用原色;自己帶深色底的元件(例:`.pill.posted`)字維持亮色。

- 深色版型（dark.css 為主）,白色版型為輔
- **禁用** emoji 與其他裝飾性符號（見 [memory feedback-no-emoji]）
- icon 只用功能性（搜尋、過帳、刪除、匯出),不用情緒性（笑臉等）
