買賣串接規格

草稿 · 2026-10-14 · 還沒有實作 · 要你定的七件事在最下面

用這套 POS 的經銷商可以互相買賣;外面的系統照同一份規格也接得進來。錢不經過平台,只管帳。

現在有的、還沒有的

買家那一半 已經有

看商品與進價、下單、查單、到貨變進貨單。POS 跟膜總裁叫貨就是照這套做的,在測試站。

賣家那一半 還沒有

讓別人看我的批發商品、對我下單;我接單、出貨,對方收貨入庫。這一份規格主要在補這一半。

管什麼、不管什麼

管

  • 誰可以跟誰買
  • 看商品與價錢
  • 下單、接單、出貨
  • 收貨入庫
  • 對帳:哪幾張單、多少錢、收了沒

不管

  • 錢:不收款、不付款、不抽成
  • 叫物流(只帶託運單號)
  • 開發票(只帶抬頭與統編給賣家)
  • 退貨與瑕疵換貨(這一版不做)

兩種身分、兩種接法

同一家經銷商可以同時是賣家與買家。買家以門市為單位:一間門市一個收貨地點、一份往來。

接法什麼時候用怎麼認人
平台內買賣雙方都用這套 POS不用金鑰。賣家在 POS 裡核准這個買家就通了
對外有一方不在這套 POS(別人的 POS、廠商自己的系統)賣家發一把金鑰給買家的一間門市

兩種接法是同一份規格,資料長得一樣。之後有經銷商換系統、或廠商要接進來,不用重談格式。

一張單的一生

買家 看商品→ 下單→ 收貨入庫
賣家 待接單→ 已接單→ 部分出貨→ 已出貨→ 已完成 已拒絕 已取消
  • 一張單可以分好幾次出貨,買家照每一次出貨收貨。
  • 手機、平板這類帶序號的,出貨時帶著每一台的序號。買家收貨直接變成自己庫存裡的那幾台,不用再刷一次。
  • 價錢只有賣家算。買家下單不送價錢,以賣家回的為準。
  • 同一張單只會成立一次。斷線了再送,不會變成兩張(現在叫貨就是這樣做的)。
  • 訂單現在的樣子以賣家那邊為準。賣家事後改單,買家再查就是新的。

誰看得到什麼

平台上的經銷商是互相競爭的,所以預設都收著。

買家看得到

  • 賣家開放給他的商品
  • 他自己的價錢
  • 他自己下的單

看不到賣家的成本、別的買家的價錢。

賣家看得到

  • 下給他的單
  • 那張單的收貨資料與聯絡方式

看不到買家的庫存、買家跟別家買了什麼。

沒被核准的買家,連這個賣家有沒有在賣都不知道。

共同語言

手機、平板、穿戴

用平台的標準機型。買賣雙方講的是同一支,買家不用連品名,直接對到自己的品號。

配件與其他

沒有共同語言。賣家給自己的料號與品名,買家用「品名連連看」連一次,之後自動。

管帳

  • 每張單有金額、付款方式(雙方講好的文字)、收款記號(賣家自己按:未收款或已收款)。
  • 對帳單:某一段期間跟某一個對象的每一張單、出貨金額、收了沒、合計。買賣雙方各拉各的,數字同一個來源。
  • 價錢含不含稅,每個賣家講清楚一次。
  • 不做收款沖帳、預收、抽成。

要你定的七件事

誰可以跟我買

建議:賣家核准每一個買家,才看得到商品與價錢。另一種是設成公開批發價。

庫存露多少

建議:只露「有貨、缺貨」。同業看得到數量,等於看得到我的底。

買家可不可以自己取消

建議:賣家接單之前可以;接了之後要聯絡賣家。

中古機批發要不要一起做

建議:第一版先做全新機與配件。中古機每一台機況與價錢不同,要「一台一台上架」,另開一版。

管帳做到哪

建議:每張單的收款記號,加上對帳單。不做沖帳。

對外的金鑰誰發

建議:賣家自己在 POS 後台發給買家,弄丟了自己作廢重發。

平台內買賣,兩邊的單怎麼開

建議:賣家按出貨,自動開一張銷貨單並扣庫存;買家按收貨,自動開一張進貨單。兩邊各按一次,像調撥的派發與確認。

給寫程式的人

現有的 v1(看商品、下單、查單)每一支照舊能用。v2 多了下面這些;每個賣家用「會哪些」講自己做了哪幾項,買家的畫面照它顯示。完整的欄位在專案的 docs/api/買賣串接規格_v2_草稿.md。
