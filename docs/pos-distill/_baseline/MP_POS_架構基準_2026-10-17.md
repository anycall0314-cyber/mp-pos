## 1. 技術組成

- 後端 Django 5.1 + DRF + PostgreSQL 16（`AGENTS.md` 核心 stack）；前端 React 18 + Vite + TypeScript + TanStack Query。
- 業務動作寫在各 app 的 `services.py`，viewset 只負責 HTTP 與交易（`AGENTS.md` 慣例）。
- 前端唯一導覽設定 `frontend/src/nav.ts`：今日總覽 + 8 個業務入口（銷貨作業、進貨入庫、商品庫存、客戶會員、維修作業、電信作業、門市帳務、統計分析）+ 平台管理、系統設定。

## 3. 帳號、角色與權限

- 三種角色：平台管理員、經銷商管理員、店員（`backend/apps/tenants/models.py:389`）。
- 店員逐項權限勾選，清單只有一份：`backend/apps/tenants/abilities.py:50`（作廢銷貨、銷退、作廢進貨、商品建檔、盤點、進貨、中古收購、雜支、營業日報、廠商叫貨、發票字軌、批發出貨、各報表…）。
- 只限管理員的：電信方案增改（`parties/views.py`）、盤點核准、客戶排行、公司備份與還原、廠商金鑰。
- 登入：DRF Token；閒置 2 小時登出（`frontend/src/lib/idleLogout.ts`）。

## 8. 不可違反的決策（比較與規格必須逐條對照）

出處：`AGENTS.md`「必懂的設計決策」「業務規則速查」「慣例」「使用者偏好」，全文在 `docs/decisions.md`。

1. **儲存即生效**：沒有過帳 / 未過帳中間狀態，取消一律作廢（`is_void`）。
2. **庫存以序號為單位**；配件走 `StockBalance`；不允許負庫存。
3. **成本全公司加權平均、不分倉**（防店員挑低成本機賣）；中古機例外用個別成本。
4. **計入現金 / 計入毛利雙旗標**（`counts_cash` / `counts_margin`）。
5. **單據金額整數元、四捨五入**（明細金額、未稅、稅額、總額），規則只有 `apps/core/money.py` 一份；**成本與平均成本保留到分**（兩位小數），不套整數規則；已存的單顯示存下的數字、不重算。
6. **同一份建單只成立一次**（`Idempotency-Key`）。
7. **先鎖再檢查、再改**（`apps/inventory/locking.py`），每個動庫存或序號的動作都在交易內。
8. **單號不重用**（`apps/core/numbering.py` 與 `DocNumberFloor`）。
9. **所有業務表帶 tenant**，關聯與篩選限縮到自己公司；API 只回 JSON。
10. **每張新表都要在備份登記表分類**。
11. **畫面規約**：四種版型（錄入頁、Master-Detail、報表頁、工作台）；連續刷條碼的單據用工作台、掃一下加一行、**不用彈出視窗當主作業區**；入口名稱四個字；只有一個 React app；繁體中文；不用 emoji。
12. **自動產生的欄位**（`sku` / `code` / `no`）前端不顯示也不輸入。
13. **銷退只能整張退**；退回的序號隔離為 `returned`，要手動轉回才能再賣。
14. **電信方案只有管理員能改**；門號有兩個佣金。
15. **舊 POS 資料**：owner 明講之前不放進正式站。
16. **一個規則只有一份程式**（例：合約到期、維修毛利、報表指標、權限清單、匯出寫法）——新規格不得另寫一份平行的算法。
