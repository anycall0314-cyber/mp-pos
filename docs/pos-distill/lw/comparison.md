# lw 與 MP POS 比較

> 依據的基準：`docs/pos-distill/_baseline/MP_POS_架構基準_2026-10-17.md`（commit `fbec2bf`）。
> MP POS 現況一律附 `檔案:行號`（相對 `backend/apps/`）；分類判準見 `references/conventions.md` 第 7 節。
> 每一項都要對過基準檔的「不可違反的決策」（下稱 D1～D16）。
> 注意 lw 是盤商系統、MP POS 是通訊行門市系統：很多 lw 功能對 MP POS 只在「批發」這一塊有對應。

## 2. 逐項

### CMP-001 批發客戶的結帳方式

| 項目 | 內容 |
|---|---|
| 競品做法 | 客戶主檔有結帳方式多選：日結／週結／月結／現金／拓銷／寄賣（【事實】高，FD-B2B-042，EV-009） |
| MP POS 現況 | `TradePartner.terms` 一個自由文字「付款方式」預設「匯款」（`trade/models.py:85`）；`TradeSetting.default_terms`（`:55`） |
| 差異 | lw 把「什麼時候結」當客戶屬性，直接影響應收何時到期；MP POS 只記怎麼付 |
| 分類 | C |
| 理由 | 每家通訊行對同業的結帳週期不同；給預設值（現在的「匯款／逐單」）、各家自訂選項。不動核心資料模型（加欄位＋選項表） |
| 衝突的決策 | 無 |
| 影響範圍 | `TradePartner` 加欄位；`trade/payments.py` 到期日計算；批發單畫面 |
| 建議下一步 | 寫規格（併入 CMP-006） |

### CMP-002 批發客戶狀態五種

| 項目 | 內容 |
|---|---|
| 競品做法 | 潛在客戶／拒絕往來／暫停往來／正常往來／停止營業（【事實】中，FD-B2B-043） |
| MP POS 現況 | `TradePartner.Status`：未核准／往來中／不往來（`trade/models.py:72-75`） |
| 差異 | lw 多「暫停往來」（暫時不出貨但保留）與「停止營業」（歷史保留） |
| 分類 | A |
| 理由 | 只加兩個選項值，不改結構；對所有通訊行都適用；「暫停」是實務常見狀態 |
| 衝突的決策 | 無 |
| 影響範圍 | choices、接單檢查（`trade/holds.py` 或訂單服務）、畫面 |
| 建議下一步 | 寫規格 |

### CMP-003 客戶母公司自關聯

| 項目 | 內容 |
|---|---|
| 競品做法 | 客戶可指定「總公司」（【事實】欄位；自關聯【推論】，FD-B2B-039） |
| MP POS 現況 | `TradePartner` 無上層；`buyer_store` 只是文字（`trade/models.py:280`） |
| 差異 | 連鎖同業多店下單時，lw 可彙總到母公司對帳 |
| 分類 | B |
| 理由 | 值得做但要先決定對帳主體（母公司 or 分店）；牽涉應收歸屬 |
| 衝突的決策 | 無 |
| 影響範圍 | `TradePartner` 自關聯、`payments.ledger` 彙總層 |
| 建議下一步 | 待 owner 決定是否有連鎖同業的需求 |

### CMP-004 收件日、預設出貨倉、自取倉

| 項目 | 內容 |
|---|---|
| 競品做法 | 客戶主檔記固定收件星期、預設出貨倉、分倉取貨倉（【事實】中，FD-B2B-040、044） |
| MP POS 現況 | `TradeShipment.warehouse` 每張出貨選（`trade/models.py:363`）；`TradeOrder.delivery_method` 文字（`:286`） |
| 差異 | lw 把物流排程資訊放在客戶層 |
| 分類 | B |
| 理由 | 收件日屬於有自家車隊的盤商需求；MP POS 的通訊行同業買賣多為宅配／自取。預設出貨倉可借鏡但要配合門市鎖定（D9） |
| 衝突的決策 | 無 |
| 影響範圍 | `TradePartner` 加 default_warehouse；出貨畫面預設 |
| 建議下一步 | 只做「預設出貨倉」部分，收件日不做 |

### CMP-005 客戶信用額度

| 項目 | 內容 |
|---|---|
| 競品做法 | 可出貨額度＝上月佣金轉額度＋優惠額度＋本月佣金－本月出貨優惠價（【推論】中，INF-007，三列驗算一致）；總額度角色不明（Q-012） |
| MP POS 現況 | 只有欠款：`trade/payments.py:38` `ledger()` 逐單欠款、收款由舊到新分、溢收；無額度、無上限擋單 |
| 差異 | lw 以佣金養額度（下游店的佣金轉成可拿貨額度），出貨先吃額度再成應收 |
| 分類 | B |
| 理由 | 目標（給同業信用上限、超過就擋單）有價值；但 lw 公式綁門號佣金，通訊行同業買賣多半沒有佣金來源 → 重新設計為「信用額度上限＋目前欠款」擋單。公式本身只有推論，不能分 A |
| 衝突的決策 | 無；需遵守 D16（欠款只算一次，用 `ledger()`） |
| 影響範圍 | `TradePartner.credit_limit`；接單／出貨檢查；畫面顯示 |
| 建議下一步 | 寫規格：credit_limit ＋ 用 ledger().due 擋單 |

### CMP-006 應收一單一筆、收款／銷帳兩步、收款部門

| 項目 | 內容 |
|---|---|
| 競品做法 | 每張出貨／退貨一筆應收；收款填日期＋部門，再由另一人銷帳；三個日期（【事實】高，FD-ARP-001～007；兩步意義 Q-027） |
| MP POS 現況 | 收款是一筆金額（`TradePayment` `trade/models.py:415`），顯示時由舊到新分配、不存分配（`payments.py:38-55`，決策「不產生傳票」） |
| 差異 | lw 是「逐單沖帳＋會計覆核」；MP POS 是「池子分配」 |
| 分類 | B |
| 理由 | 逐單沖帳對會計對帳有幫助，但推翻既有「不存分配」決策要 owner 明講；建議只借「對帳單呈現」與「到期日」，沖帳邏輯維持池子 |
| 衝突的決策 | 批發決策第 6 點（不存分配結果、不產生傳票）；D16 |
| 影響範圍 | `payments.py`、報表 |
| 建議下一步 | 寫規格時只納入 CMP-001 到期日 ＋ CMP-007 對帳單；沖帳方式改變另案由 owner 決定 |

### CMP-007 對帳單

| 項目 | 內容 |
|---|---|
| 競品做法 | 應收帳款對帳單：客戶、銷售／收款日期區間、狀態、彙總／明細（【事實】高，FD-ARP-013） |
| MP POS 現況 | 基準第 9 節缺口：無對帳單；`ledger()` 有每單欠多少的資料 |
| 差異 | 資料已在，缺一張可匯出給同業的表 |
| 分類 | A |
| 理由 | 只是把 `ledger()` 結果排成期間報表；不改模型；匯出走 `frontend/src/lib/csv.ts`（D16） |
| 衝突的決策 | 無 |
| 影響範圍 | 報表頁、匯出 |
| 建議下一步 | 寫規格 |

### CMP-009 批發退貨逐序號

| 項目 | 內容 |
|---|---|
| 競品做法 | 退貨管理刷「商品序號＋新增」建退貨單，退貨單對應原出貨單（【事實】欄位；流程【推論】，FD-B2B-029～031，EV-007） |
| MP POS 現況 | 銷退只能整張退（`sales/models.py:449` 文件字串；D13）；批發出貨開的銷貨單不能從銷貨端作廢（基準 B2B 列） |
| 差異 | 同業退一台很常見（整張 10 台退 1 台） |
| 分類 | B |
| 理由 | 與 D13 直接衝突；若要做，應設計成「批發出貨取消單台」而非改銷退規則 |
| 衝突的決策 | D13 |
| 影響範圍 | `trade` 出貨取消邏輯、庫存回沖、`ledger()` |
| 建議下一步 | 待 owner 決定是否開放「批發單台退回」 |

### CMP-010 退貨單可刪除 — D
lw 有「刪除」連結（業務停用，【事實】EV-007）。MP POS 一律作廢（D1）。不採用。

### CMP-011 佣金表按月版本化

| 項目 | 內容 |
|---|---|
| 競品做法 | 年月×電信×套餐×專案→佣金；客戶×電信×申辦類別×年月→套餐（【事實】高，FD-TEL-009～013，INF-013、014） |
| MP POS 現況 | 佣金寫在方案上：`TelecomPlan.commission`、`company_commission`（`parties/models.py:119`、`:122`）；銷貨時存快照（`sales/models.py:257`、`:266`） |
| 差異 | 電信佣金每月變動，MP POS 要改方案才能換佣金；歷史單靠快照才不受影響 |
| 分類 | B |
| 理由 | 月版本化有價值（每月改佣金不用建新方案），但 lw 的「客戶別套餐」是盤商對下游的機制，通訊行不需要 → 重新設計為「方案佣金生效日期區間」 |
| 衝突的決策 | 無（快照已符合 D5 精神） |
| 影響範圍 | `TelecomPlan` 佣金拆成子表（生效起迄）；開單時取當日有效佣金 |
| 建議下一步 | 寫規格 |

### CMP-012 申辦類別 8 種 — C
lw：新申辦／NP／續約／預付卡／加掛／換補卡／行動裝置保險／服務異動（【事實】高）。MP POS：`TelecomPlan.Kind` 新辦／續約／攜碼（`parties/models.py:87-90`）。加掛、換補卡、保險是門市也會做的事，但各家有無做不一定 → 租戶可設定的類別清單，預設三種。不衝突。

### CMP-013 開通紀錄獨立 — 待驗證後再分類
lw 有開通明細功能（【事實】），MP POS 上線日在銷貨明細（`sales/models.py:277` `activation_date`）。要先確認 lw 開通是否可獨立於出貨（Q-019）；若門市都是開單即上線，現況夠用。

### CMP-014 門號佣金往來帳 — 待 owner 決定
29 種正負項目（【事實】高，FD-ARP-009）是盤商與下游的結算；MP POS 門市只需「電信給我多少」。若 owner 日後要做盤商角色才有意義。B。

### CMP-015 退件流程 — 待 owner 決定
同上，B。門市版可簡化為「退件 → 佣金回沖」一個動作。

### CMP-016 進貨兩段式 — D
lw 先建進貨訊息再刷序號（INF-015）。違反 D1 儲存即生效；MP POS 已有 `vendor_orders` 叫貨單承擔「預告」角色。不採用。

### CMP-017 手機補貼入帳 — 待 owner 決定
原廠按月給的機型補貼（【事實】欄位，FD-PUR-007）會影響實際成本。MP POS 成本只在進貨單（D3 加權平均）。做的話是「事後成本調整單」，影響加權平均 → 完整審查。B。

### CMP-018 轉倉「已退貨」

| 項目 | 內容 |
|---|---|
| 競品做法 | 轉倉中／已收貨／已退貨三狀態（【事實】高，FD-TRF-003） |
| MP POS 現況 | `TransferOrder.Status` 派發中／已完成（`transfers/models.py:17-19`） |
| 差異 | 目的門市收到不對的貨時，MP POS 只能完成再反向調撥 |
| 分類 | A |
| 理由 | 加一個狀態與一個「退回」動作，序號回來源倉；符合 D7 鎖定流程 |
| 衝突的決策 | 無 |
| 影響範圍 | `transfers` 狀態、服務、`StockMovement` 類型 |
| 建議下一步 | 寫規格 |

### CMP-019 盤點類別 — C
日常／調店／抽查／離職（【事實】高）。MP POS `StockCount` 無類別（`inventory/models.py:366-377`）。加一個可選類別欄，預設清單四種、各家可改；不影響核准流程。

### CMP-020 盤失扣款審核 — D
人事賠償流程不屬 POS 核心；owner 原則「資料做滿、客製外放」。不採用（盤差數字已在 `StockCount`）。

### CMP-021 型號層補貨旗標

| 項目 | 內容 |
|---|---|
| 競品做法 | 型號有 補貨 Yes/No、清倉、門市庫存上限、最大銷售量（【事實】高，FD-PRD-009～011；意義 Q-025） |
| MP POS 現況 | `Product.lifecycle_status`（`catalog/models.py:257`）、`safety_stock`（`:244`）、`replenish_days`（`:293`） |
| 差異 | 大致對應；lw 多「不再補貨」明確旗標 |
| 分類 | A |
| 理由 | `lifecycle_status` 若尚無「停止補貨」值，加一個值即可 |
| 衝突的決策 | 無 |
| 建議下一步 | 寫規格（小） |

### CMP-022 人工型號編號 — D
違反 D12（sku 系統產生、不輸入）。不採用。

### CMP-023 業務看全公司 — 待 owner 決定
lw 業務角色看得到所有倉的出貨單（【事實】EV-004），MP POS 店員鎖門市（`core/warehouse_scoping.py:46`）。盤商業務跨倉是其業務性質；通訊行不需要。但「業務／內勤」兩個負責人維度（FD-B2B-045）可借鏡為批發客戶的負責人。B。

### CMP-024 銷售類型維度 — 待驗證後再分類
15 種銷貨種類（【事實】）只看到查詢條件，未見在開單時怎麼決定（Q-006）。MP POS 用 `Product` 旗標推導。驗證後再分。

### CMP-025 門市群組 — 待 owner 決定
組織群組多對多（【事實】FD-RPT-003），用於報表與公告。MP POS 只有 Tenant→Warehouse。多門市經銷商有「區」的需求時有用；C（各家自建群組）。

### CMP-027 UI 版型 — D
查詢頁與結果分離、報表另開視窗、彈出視窗快查、整頁 PostBack（【事實】EV-002～005、011）。違反 D11（不用彈出視窗當主作業區、四種版型）。不採用；只借規則不借外觀。

### CMP-028 付訂金狀態

| 項目 | 內容 |
|---|---|
| 競品做法 | 銷貨單狀態「全額支付／付訂金」；捷徑頁有「退款」入口退現金訂金（【事實】中，FD-SAL-005、011，EV-025、026） |
| MP POS 現況 | 付款合計必須等於含稅總額（`sales/services.py:363-366` `_validate_payments`；`:545`）；無訂金狀態 |
| 差異 | 預購、缺貨先收訂在通訊行很常見；MP POS 目前只能另開「訂金」虛擬商品 |
| 分類 | B |
| 理由 | 與「儲存即生效、付款＝總額」設計衝突；需設計成「訂金單」（獨立單據，收現金、不扣庫存）＋ 正式銷貨時沖抵，而非讓銷貨單有未付清狀態 |
| 衝突的決策 | D1 精神（無中間狀態）；付款＝總額規則 |
| 影響範圍 | 新單據類型、現金日報、作廢回沖 |
| 建議下一步 | 待 owner 決定是否要訂金功能 |

### CMP-030 刷卡授權碼與分期資訊 — C
授權碼、期數、配合銀行、利息類型（【事實】高，FD-SAL-002、004）。MP POS `SalesOrderPayment.method`＋`amount`＋`note`（`sales/models.py:363-375`）。做法：付款方式若標為「刷卡／分期」，付款列可填附註結構（授權碼、期數、銀行）；哪些付款方式要填什麼由公司設定（付款方式本就公司自訂，基準第 6 節）。不改金額規則。

### CMP-031 每日結帳按店員、短溢收、鎖當日

| 項目 | 內容 |
|---|---|
| 競品做法 | 每人每日一筆結帳：各收款來源合計、應繳 vs 實收、短收／溢收；結帳後當日不能再銷貨退貨退款（【事實】高，FD-CSH-001～003、FD-SAL-012；鎖的範圍 Q-032） |
| MP POS 現況 | 營業日報以門市為單位、可篩業務員（`sales/daily_report.py:84-89`）；`CashAdjustment` 記差額（`cash/models.py:97`）；不鎖單 |
| 差異 | lw 把「誰收的錢、短了多少」做成每日動作；MP POS 只有報表＋手動調整 |
| 分類 | B |
| 理由 | 「結帳後鎖當日」會擋補登與作廢，與 D1（作廢永遠可行）衝突；但「每人每日交帳：應繳 vs 實收，短溢收寫入現金調整」有價值。重新設計為：日報加「交帳」動作，產生 `CashAdjustment`，不鎖單 |
| 衝突的決策 | D1 |
| 影響範圍 | `cash`、`sales/daily_report.py`、權限 `CASH_OPS`（`abilities.py:34`） |
| 建議下一步 | 待 owner 決定（owner 先前已決定走「現金流報表＋自動標已付」路線，見 pos-system 筆記） |

### CMP-032 欠客 — 待驗證後再分類
缺貨先收款、之後補貨，單上有「欠客單號」，毛利統計可排除（【事實】欄位；流程 Q-031）。MP POS 無。與 CMP-028 訂金是同一族問題，一起決定。

### CMP-033 單上顯示毛利 — D
D16（毛利算法只在 `analytics/catalog.py:358`）；且店員介面顯示毛利違反成本敏感欄位原則（基準第 3 節：成本毛利誰看得到由權限決定）。不採用。

### CMP-034 九個入口磚 — D
D11：連續刷條碼的單據用工作台、不用多入口分流。「客退換貨要先退再賣」MP POS 本就如此（銷退＋新銷貨）。不採用。

### CMP-035 會員到期日空值篩選 — A（只借篩選）
會員＝門號合約一列（【事實】表頭；【推論】一人多列，FD-MBR-001）MP POS 已把人與門號分開，不改。可借「合約到期日為空值」「上線日期區間」篩選加進會員／合約查詢（`sales/contracts.py` 規則不變）。小、不動模型。

### CMP-036 資費結算含審核 — 待 owner 決定
代收資費另結、含違約金、審核人員（【事實】FD-CSH-004）。MP POS `PhoneBillCollection`（`cash/models.py:185`）無審核。是否需要主管審核屬流程偏好 → B／C 之間，待 owner。
