## P1：先修訂主動作外觀，再延續遷移

**證據：** `docs/ui-controls.md:9,39` 仍要求主動作藍底；`AGENTS.md`「程式碼定位」仍寫主要按鈕藍色；`Button.tsx:29` 把 primary 對應到原 `.btn.primary`；`styles.css:479–489,5794–5808` 保留實心藍及 hover。新元件目前沒有改變這項外觀。

**建議寫入正式規範的方向：**

| 角色 | 下一版外觀目標 |
|---|---|
| 新增、查詢、複製、匯出、返回等一般動作 | 白底或透明底、清楚深色文字、細框或文字型；不要使用鮮藍實心 |
| 工作區主要動作／儲存 | 以位置、字重及柔和藍灰文字／框線辨識，預設仍為輕量底色；每一作用中工作區至多一個強調動作 |
| 最終交易提交 | 先沿用輕量主動作；若特定掃碼／結帳情境需要更強強調，列明具名例外及樣張，不自行全面恢復實心藍 |
| 分頁 | 透明底、文字與底線；不加整塊實心選取底 |
| 少量互斥條件 | 未選透明／頁面底色；選中輕微中性底、字重或標記，不使用 primary |
| 下拉／搜尋欄 | 預設與頁面底一致，保留可辨識邊框；hover／focus 才輕微改變，不把所有欄位鋪成灰色磚塊 |
| 狀態／錯誤／兩段確認 | 維持文字與必要語意色；保留既有 armed、防誤觸、錯誤和停用意義 |

這是視覺層級修正，不能靠降低整個元件 opacity、讓文字變淡或移除鍵盤焦點達成。也不要只淡化 `--accent-fill` 卻保留白字。真正的布林開關仍須清楚區分開／關，不套用分頁的透明外觀。

**修改位置：** `docs/ui-controls.md`、必要的 `docs/ui-patterns.md`／`AGENTS.md`索引文字、`frontend/src/components/ui/Button.tsx` 的註解與介面、`frontend/src/styles.css` 共用按鈕與日間覆寫、`ControlsShowcasePage.tsx`。

**驗收：** 三個 B1 樣板的普通導覽、查詢、篩選、複製、建立入口不再有高飽和實心藍；主動作仍容易找到；明暗主題的文字、focus、disabled、pending、error、armed 都能辨識。具名例外另列，不能用「主要按鈕」四個字把所有舊實心樣式保留下來。

## P1：拆開控制項與表格選取色

**證據：** `styles.css:558–567` 的 SegmentedControl 使用整組外框、每項底色與 `--row-selected`；日間最終 token 在 `styles.css:5777` 為 `#eef2ff`。工具列欄位在 `styles.css:585–590` 預設使用 `--panel-2`。

**修改方式：** 在共用層定義控制項專用的預設、hover、selected token；不要借用表格列選取色。選取以中性輕底搭配文字／標記，焦點另行呈現；移除沒有辨識用途的重複鋪底與分隔。

**驗收：** 維修「全部／自修／委外」保持單選及原鍵盤操作；選中與 focus 可區分；換選項不改動任何業務資料。比較廠商叫貨三個欄位、維修選項與歐睿搜尋列，未選控制項不再連成大片色塊。

## P2：後續遷移仍需涵蓋的實心樣式

**證據：** `styles.css:2096–2100` 的 `.tab-switcher-item.active`／`.ia-tab.active` 仍是實心藍。引用包含商品、來源、設定、庫存警示、盤點與中古收購。合約及銷貨付款方式另有 `.wb-chip.on`，緊湊商品表單另有 `.pf-tab.active`。

本次源碼掃描仍有 50 處 `legacy-tab` 規則命中，整份 controls baseline 為 215 處；這是規則命中數，不是頁面數，也不是 215 個功能錯誤。B1 原本只涵蓋三頁指定區塊，不能把後續範圍都當成這批漏做。

**修改方式：** 按原 B2–B4 分批依用途遷移。先從商品、來源與系統設定等常見頁面收斂；搜尋、逐列「去進貨」、複製等輔助動作降為一般／文字型。廠商叫貨紀錄的「更新進度」「複製內容」也要逐項判斷，不能只驗頁首 Tabs。

**驗收：** 每批列頁面及控制區域、前後截圖、剩餘基線；分頁／篩選／付款方式都不借用 primary 表示選中。保留路由、權限、草稿、交易與確認流程；確認無引用後才移除舊 CSS。

## P2：補上能維持新外觀的守門與視覺驗收

**證據：** 現有 `controlsPolicy.mjs` 只涵蓋部分 class／三元式；以下寫法可通過目前掃描：`wb-chip on`、`Button variant={selected ? 'primary' : 'default'}`、同區多顆 primary、`cx('btn', selected && 'primary')`。共用 CSS／token 改成重底色也不一定會被守門攔下。部署腳本目前只 build，不能描述成部署前會自動攔截。

**修改方式：**

1. 補上述已驗證的漏網寫法與對應反例測試；避免讓新頁複製既有豁免。基線只能下降。
2. 在展示頁固定代表角色及所有互動狀態，加入明暗主題的可重複畫面／computed-style 檢查；除了 class 存在，也核對真正渲染的背景、文字、框線與焦點。
3. 對每批作用中的工作區列出主動作用途及例外，用人工畫面核對補足靜態掃描；不要宣稱一條 regex 能保證語意正確。
4. 每次新增控制項先讀更新後規範、使用共用元件並補展示例；交付同時報測試結果和畫面結果。

**驗收：** 新寫法不能繞過同一套規範；將展示頁的分頁／篩選故意改回實心，相關視覺檢查能指出差異。樣張固定資料、視窗、主題及狀態，不把舊樣式直接重新錄成通過基準。依既有規範驗 1366／1024／768／390px、200% 縮放與觸控尺寸。
