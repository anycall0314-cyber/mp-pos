# pos-distill 共用規則

所有系統、所有模組都用同一套編號、標記、信心與格式，日後才能跨系統合併比較。

## 1. 編號

| 種類 | 格式 | 範例 | 放在哪 |
|---|---|---|---|
| 證據 | `EV-<系統>-<YYYYMMDD>-<NNN>` | `EV-ored-20261017-003` | `evidence/index.md` |
| 欄位 | `FD-<模組代碼>-<NNN>` | `FD-SAL-012` | `field-dictionary.md` |
| 互動關係 | `REL-<NNN>` | `REL-027` | `relations.md` |
| 流程 | `FL-<模組代碼>-<NN>` | `FL-SAL-02` | 模組檔第 2 節 |
| 狀態轉換 | `ST-<模組代碼>-<NN>` | `ST-STK-01` | 模組檔第 3 節 |
| 例外 | `EX-<模組代碼>-<NN>` | `EX-PUR-04` | 模組檔第 4 節 |
| 架構推論 | `INF-<NNN>` | `INF-008` | `architecture-inference.md` |
| 待驗證問題 | `Q-<NNN>` | `Q-015` | `open-questions.md` |
| 比較項 | `CMP-<NNN>` | `CMP-021` | `comparison.md` |
| 改善規格 | `SPEC-<NNN>` | `SPEC-004` | `specs/` |
| 寫入測試授權 | `AUTH-<NNN>` | `AUTH-002` | `auth/` |

- 編號在同一個系統內流水、只增不減；作廢的編號保留並標「作廢（原因）」，不重用。
- 在系統資料夾以外（Blueprint、README、跨系統比較）引用時一律加系統代號：`ored/SPEC-001`、`ored/CMP-003`。
- `<NNN>` 不足補 0。系統代號小寫英數。

## 2. 三種標記

| 標記 | 意思 | 必附 | 信心上限 |
|---|---|---|---|
| `【事實】` | 在畫面或操作結果上直接看到 | 至少一個 EV | 高 |
| `【推論】` | 由事實推出，畫面沒有直接顯示 | 依據（FD / REL / EV 編號）＋推理一句 | 中 |
| `【待驗證】` | 猜測、二手資訊、舊資料、owner 口述但未查證 | 驗證方法＋Q 編號 | 低 |

- owner 口述的競品行為：先標【待驗證】，註明「owner 口述 <日期>」；看到畫面後再升級。
- 舊文件（例如之前的歐睿整理）：標【待驗證】並註明原檔，重新觀察過才可升為【事實】。
- 競品的資料表、程式、內部公式：最多【推論】（有廠商正式文件可標【事實】，EV 指向該文件）。
- 「沒看到」不等於「沒有」：寫「未觀察到（查過 <畫面>）」，標【推論】。

## 3. 信心等級

| 等級 | 條件 |
|---|---|
| 高 | 兩個以上獨立證據一致（不同畫面、不同操作或不同資料）；或一次授權寫入測試有完整前後狀態 |
| 中 | 單一直接證據；或推論有兩個以上事實支持且沒有反例 |
| 低 | 只有間接線索（欄位名稱、版面位置、舊文件、口述）；或單一事實支持的推論 |

## 4. 證據

每個 EV 在 `evidence/index.md` 一列，欄位：

| 欄 | 寫法 |
|---|---|
| EV 編號 | 見上 |
| 時間 | `YYYY-MM-DD HH:mm`（台北時間） |
| 帳號角色 | 例：門市管理員、店員（不寫帳號名稱） |
| 頁面 | 選單路徑 ＋ 網址路徑（去掉 `?` 後面的查詢值） |
| 操作步驟 | 1. … 2. …（看得懂就能重做） |
| 觀察結果 | 一兩句 |
| 證據類型 | 文字擷取 / 截圖 / 錄影 / DOM 屬性 / 網路請求欄位名 / owner 提供 / 廠商文件 |
| 檔案 | `captures/<EV>.md` 或 `media/<EV>_<簡述>.png`；對話中看過但沒存檔寫「未存檔」 |
| 遮罩 | 已遮罩 / 不含個資 / 未存檔 |
| 驗證結果 | 一致 / 不一致（寫跟哪個 EV） / 單次 |
| 支持的結論 | FD / REL / INF / CMP 編號 |

- 文字擷取（頁面文字、DOM 屬性）優先：好搜尋、好遮罩。遮罩後存 `evidence/captures/`，可以進 git。
- 截圖、錄影存 `evidence/media/`（已設定不進 git），檔名以 EV 編號開頭。不上傳到任何外部服務。
- 證據只在對話中出現、沒有存檔的，該結論信心最多「中」。

## 5. 個資遮罩

只記欄位，不記客人。真的需要範例值時：

| 資料 | 怎麼寫 |
|---|---|
| 客人姓名 | `王○○`，或直接寫「（姓名）」 |
| 電話 | 只留末 3 碼：`09xx-xxx-123` |
| 身分證、護照、居留證 | 一個字元都不記：「（證號）」 |
| 地址 | 最多到縣市 |
| 生日 | 不記，寫「（日期）」 |
| IMEI / 序號 / SIM 卡號 | 只留末 4 碼 |
| 統一編號 | 公司客戶可留，個人一律不記 |
| 員工姓名 | 寫角色（店員 A、店長） |
| 金額、數量 | 可以記（觀察計算規則需要），但不要搭配可識別的客人 |

- 截圖有客人資料：先遮罩再存，或改成文字描述。
- 不匯出整份客戶名單或交易明細；需要量級時只記筆數。
- 網路請求只記路徑與欄位名稱，不記值。

## 6. 欄位字典用詞

- **資料型態**：文字、整數、金額、百分比、日期、日期時間、布林（勾選）、單選（列舉，列出選項）、多選、
  參照（→ 某實體）、識別碼（IMEI / SN / 卡號 / 發票號）、電話、統編、檔案。
- **必填條件**：一律、條件式（寫條件）、選填、不明。
- **資料來源**：使用者輸入、系統帶入（從哪裡帶）、系統計算（公式）、系統產生（流水號規則）、外部（電信 / 財政部 / 廠商）。
- **驗證規則**：長度、格式、範圍、唯一性、跨欄位條件；訊息原文只節錄短句。

## 7. A / B / C / D 判準

| 分類 | 什麼時候 | 必寫 |
|---|---|---|
| A 可以直接借鏡 | 競品做法有【事實】支持、跟 MP POS 不可違反的決策都不衝突、不需要改資料模型的核心（只加欄位或畫面）、每家通訊行都適用 | 要動哪裡 |
| B 需要重新設計 | 目標值得做，但競品做法跟 MP POS 決策衝突、有資料正確性風險、步驟太多，或競品做法只有推論 | 衝突點與重新設計方向 |
| C 適合成為租戶可設定 | 不同通訊行有合理的不同做法（例：佣金規則、保固天數、預設值、要不要某個確認步驟），MP POS 給預設值、各家可改 | 設定放哪一層、預設值、改了之後舊單怎麼辦 |
| D 不應採用 | 違反 MP POS 決策或 owner 原則、有法規或資安風險、只對單一店有意義、或其實是競品自己的缺陷 | 理由（引用決策或證據） |

- 一個比較項只給一個分類；有疑慮時寫「待 owner 決定」並說明在 A/B/C/D 哪兩個之間。
- 競品做法只有【推論】或【待驗證】：最多 B，或標「待驗證後再分類」。

## 8. 每個檔案的結尾

每個輸出檔最下面保留「變更紀錄」：

```
## 變更紀錄
| 日期 | 做了什麼 | 相關編號 |
|---|---|---|
```

標記升級（待驗證 → 事實）、分類改變、作廢編號都要記一行。
